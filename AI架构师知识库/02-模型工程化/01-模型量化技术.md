## 1. 量化概述

### 1.1 为什么需要量化？

**大模型部署的三大挑战：**
1. **显存占用大**：LLaMA-70B FP16需要140GB显存
2. **推理速度慢**：大模型生成token延迟高
3. **部署成本高**：需要多卡A100/H100

**量化的核心价值：**
- 减少显存占用（50%-75%）
- 提升推理速度（1.5x-4x）
- 降低硬件门槛（单卡可部署大模型）

### 1.2 量化原理

**核心思想：** 用低精度数值表示高精度权重

```
FP32 (32位) → FP16 (16位) → INT8 (8位) → INT4 (4位)
精度降低    显存减半      显存减75%    显存减87.5%
```

**量化公式：**
```
W_q = round((W - Z) / S)
W_deq = W_q × S + Z

其中：
- W: 原始权重
- S: 缩放因子 (Scale)
- Z: 零点 (Zero Point)
- W_q: 量化后的整数值
```

## 2. 量化方案对比

### 2.1 按精度分类

| 方案 | 精度 | 显存节省 | 精度损失 | 适用场景 |
|------|------|----------|----------|----------|
| **FP32** | 32位浮点 | 基准 | 无 | 训练 |
| **FP16** | 16位浮点 | ~50% | 极小 | 通用推理 |
| **BF16** | 16位浮点 | ~50% | 极小 | 训练+推理 |
| **INT8** | 8位整型 | ~75% | 小 | 生产部署 |
| **INT4** | 4位整型 | ~87.5% | 中等 | 资源受限场景 |
| **FP8** | 8位浮点 | ~75% | 小 | H100等新硬件 |

### 2.2 主流量化方法

#### FP16/BF16（半精度）

**特点：**
- 最简单，无需校准
- 现代GPU原生支持（Tensor Core）
- 精度损失可忽略

**FP16 vs BF16：**

| 特性 | FP16 | BF16 |
|------|------|------|
| 指数位 | 5位 | 8位 |
| 尾数位 | 10位 | 7位 |
| 动态范围 | 较小 | 较大（接近FP32） |
| 精度 | 较高 | 较低 |
| 使用场景 | 推理 | 训练（更稳定） |

**架构师建议：** 推理首选FP16，训练推荐BF16

#### INT8量化

**两种实现方式：**

1. **PTQ (Post-Training Quantization)**
   - 训练后量化，无需重新训练
   - 使用校准数据集确定缩放因子
   - 实现简单，适合快速部署

2. **QAT (Quantization-Aware Training)**
   - 训练中模拟量化
   - 精度损失最小
   - 需要重新训练，成本高

**对称 vs 非对称量化：**
```
对称量化：Z = 0，适用于以0为中心的分布
非对称量化：Z ≠ 0，适用于任意分布
```

#### GPTQ（4-bit量化）

**核心思想：** 逐层量化，最小化输出误差

**算法流程：**
```
1. 选择一层权重矩阵 W
2. 计算该层输出的Hessian矩阵 H
3. 逐行量化权重，使用最优脑量化(OBQ)算法
4. 更新未量化权重以补偿误差
```

**特点：**
- 4-bit权重量化，8-bit激活
- 精度损失可控（< 1%）
- 推理速度提升2-3倍

**适用模型：** LLaMA、OPT、BLOOM等

#### AWQ（Activation-aware Weight Quantization）

**核心思想：** 保护对激活值敏感的权重通道

**关键洞察：**
- 并非所有权重通道同等重要
- 某些通道对输出激活影响更大
- 保护这些通道可显著提升精度

**与GPTQ对比：**

| 特性 | GPTQ | AWQ |
|------|------|-----|
| 算法 | 基于Hessian | 基于激活统计 |
| 速度 | 量化慢 | 量化快 |
| 精度 | 高 | 更高（通常） |
| 推荐 | 通用 | 生产首选 |

#### GGUF/GGML（端侧量化）

**特点：**
- 专为llama.cpp设计
- 支持多种量化类型（Q4_0、Q5_K_M、Q8_0等）
- CPU推理优化

**量化类型选择：**

| 类型 | 每参数位数 | 质量 | 速度 | 推荐场景 |
|------|------------|------|------|----------|
| Q4_0 | 4.5 | 中 | 快 | 资源极受限 |
| Q5_K_M | 5.5 | 良 | 较快 | 平衡选择 |
| Q6_K | 6.6 | 优 | 中等 | 质量优先 |
| Q8_0 | 8.5 | 接近无损 | 较慢 | 精度敏感 |

### 2.3 FP8量化（新一代硬件）

**H100/Ada架构支持：**
- E4M3格式：1位符号 + 4位指数 + 3位尾数
- E5M2格式：1位符号 + 5位指数 + 2位尾数

**优势：**
- 硬件原生支持，无需模拟
- 训练和推理均可使用
- 精度接近FP16，速度接近INT8

## 3. 量化实践指南

### 3.1 量化方案选型决策树

```
目标平台是什么？
├── NVIDIA GPU (A100/H100)
│   ├── 追求极致速度 → TensorRT-LLM + FP8/INT8
│   └── 平衡精度和速度 → vLLM + AWQ/GPTQ
├── 消费级GPU (RTX 4090等)
│   └── AWQ/GPTQ 4-bit
├── CPU/移动端
│   └── llama.cpp + GGUF Q5_K_M
└── 云端API
    └── 由服务商优化，无需关心
```

### 3.2 生产环境推荐配置

**配置1：企业级生产（A100/H100）**
```yaml
模型: Qwen-72B
量化: AWQ 4-bit
推理框架: vLLM
显存需求: ~40GB
吞吐量: 高
精度损失: < 2%
```

**配置2：成本敏感场景**
```yaml
模型: LLaMA-2-70B
量化: GPTQ 4-bit + 分组大小128
推理框架: vLLM/TGI
显存需求: ~35GB
部署: 单卡A100 40GB
```

**配置3：端侧/边缘**
```yaml
模型: Qwen-7B
量化: GGUF Q5_K_M
推理框架: llama.cpp
运行环境: CPU 16GB内存
延迟: 可接受
```

### 3.3 量化质量评估

**评估维度：**

1. **困惑度（Perplexity）**
   - 在验证集上计算PPL
   - 量化后PPL上升应< 10%

2. **下游任务准确率**
   - 在业务相关任务上测试
   - 与FP16基线对比

3. **人工评估**
   - 生成质量主观评价
   - 关注幻觉、流畅度

**评估流程：**
```
1. 准备校准数据集（500-1000条）
2. 准备评估数据集（业务相关）
3. 量化模型
4. 对比FP16基线
5. 若精度损失>阈值，调整量化参数
```

## 4. 推理优化技术

### 4.1 KV Cache量化

**问题：** 长序列生成时KV Cache显存爆炸

**解决方案：**
- KV Cache INT8量化
- 分页KV Cache（PagedAttention）
- 动态KV Cache压缩

**效果：**
- 长序列显存占用减少50%
- 支持更长上下文

### 4.2 混合精度推理

**策略：**
- 权重：INT4/INT8
- 激活：FP16/FP8
- 注意力计算：FP16

**优势：** 平衡精度和效率

### 4.3 算子融合

**融合操作：**
- LayerNorm + Linear
- Activation + Quantization
- Attention QKV投影

**效果：** 减少kernel launch开销，提升吞吐量

## 6. 架构师最佳实践

### 6.1 量化实施Checklist

- [ ] 确定目标平台和硬件规格
- [ ] 选择合适的量化方案（AWQ/GPTQ/FP8）
- [ ] 准备代表性校准数据集
- [ ] 量化并验证精度损失
- [ ] 测试推理性能和吞吐量
- [ ] 制定回滚方案（保留FP16版本）

### 6.2 常见陷阱

**陷阱1：校准数据不匹配**
- 问题：校准数据与生产数据分布差异大
- 解决：使用生产环境真实样本

**陷阱2：过度量化**
- 问题：追求极致压缩导致精度崩溃
- 解决：关键模型使用INT8而非INT4

**陷阱3：忽视激活量化**
- 问题：仅权重量化，激活仍FP16
- 解决：全量化（权重+激活）获得最大收益

### 6.3 性能监控指标

| 指标 | 说明 | 目标 |
|------|------|------|
| 量化后PPL | 困惑度变化 | < 基线×1.1 |
| 显存占用 | 峰值显存 | 减少50%+ |
| 推理延迟 | TTFT/TPOT | 降低30%+ |
| 吞吐量 | Token/s | 提升50%+ |

## 7. 前沿趋势

### 7.1 1-bit量化

**BitNet b1.58：**
- 权重限制为{-1, 0, 1}
- 理论能耗降低70%
- 仍在研究阶段

### 7.2 动态量化

**自适应精度：**
- 简单token使用低精度
- 复杂token使用高精度
- 平衡效率和质量

### 7.3 硬件协同设计

**专用量化芯片：**
- 4-bit矩阵运算单元
- 低精度浮点支持
- 进一步降低功耗

## 深度分析

量化技术是LLM工程化落地的基石。从FP16到INT4再到1.58-bit BitNet，精度每降低一档都在推理速度与模型质量之间产生新的权衡点。架构师需要理解的是，量化并非单纯的数值压缩——它涉及对权重分布、激活值敏感度和硬件指令集的深度适配。AWQ之所以在精度上优于GPTQ，正是因为其从激活值分布出发保护了信息量更大的通道，这种"数据感知"的思路是当前量化技术的主旋律。

生产环境中，量化方案的选择需要与推理框架、硬件平台和业务SLO通盘考量。单一维度的显存节省不足以支撑决策，必须联合评估PPL上升、下游任务准确率退化和实际吞吐增益。特别是KV Cache量化在长序列场景下的收益被严重低估——当序列长度超过4K时，KV Cache往往成为比模型权重更大的显存消耗源。

从行业趋势看，硬件原生支持的FP8/NVFP4正在重塑量化格局。Blackwell架构的FP4支持意味着未来量化将不再是部署后的"妥协"，而是训练时就规划好的第一性设计。架构师应关注BitNet b1.58和QAQ等训练时量化方法，它们在极致压缩场景下可能成为颠覆性方案。
