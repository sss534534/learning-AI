## 1. 为什么需要蒸馏与压缩

### 1.1 核心矛盾

大模型能力越强，部署成本越高。蒸馏与压缩是在**能力保留**和**部署效率**之间做最优权衡。

| 方法 | 压缩比 | 能力保留 | 适用场景 |
|------|--------|---------|---------|
| 量化 (PTQ) | 2-4x | 95-99% | 通用，几乎无痛 |
| 量化 (QAT) | 2-4x | 98-99.5% | 精度敏感场景 |
| 知识蒸馏 | 2-100x | 85-98% | 定制化小模型 |
| 剪枝 (Pruning) | 1.5-3x | 90-97% | 特定架构优化 |
| 架构搜索 (NAS) | 2-10x | 90-97% | 从零设计小模型 |

### 1.2 什么时候应该蒸馏

```
决策树：

部署成本压力大？
├── 否 → 直接用大模型（量化即可）
└── 是 → 
    需要保留多少能力？
    ├── 95%+ → QAT + 轻量蒸馏
    ├── 90-95% → 标准蒸馏 
    └── < 90% → 蒸馏+剪枝+量化联合压缩
```

### 1.3 蒸馏 vs 量化 vs 剪枝：核心取舍

三种方法不是互斥的，但在不同场景下优先级不同：

| 维度 | 量化 (Quantization) | 蒸馏 (Distillation) | 剪枝 (Pruning) |
|------|--------------------|--------------------|---------------|
| **压缩比** | 2-4x | 2-100x | 1.5-3x |
| **需要重训练** | PTQ: 否, QAT: 是 | 是 | 是 |
| **需要 Teacher** | 否 | 是 | 否 |
| **能力保留** | 95-99% | 85-98% | 90-97% |
| **硬件加速** | 原生支持（INT4/INT8） | 取决于模型架构 | 稀疏计算需要特殊支持 |
| **适用阶段** | 部署前最后一步 | 训练/微调阶段 | 训练后/微调后 |
| **风险** | 精度崩塌（极低比特） | Teacher bias 迁移 | 结构性损伤不可逆 |

**经验法则：**

```
联合压缩的推荐顺序：

Step 1: 蒸馏（减小模型规模，2-10x）
  → 从大模型学习，缩小参数量
  → 产生一个更小的 dense 模型

Step 2: 剪枝（移除冗余参数，1.5-2x）
  → 在蒸馏后的小模型上做结构化剪枝
  → 进一步减小推理计算量

Step 3: 量化（压缩到 INT4/INT8，2-4x）
  → 最后一步，最大化压缩比
  → 享受硬件加速收益

总压缩比预计: 2 × 1.5 × 4 = 12x（但不是叠加乘法，实际约 6-10x）
```

### 1.4 何时跳过蒸馏直接量化

```
蒸馏不是必须的。以下情况直接量化：

├─ 场景1: 模型已经足够小（<3B）
│    量化到 INT4 即可满足部署要求
│    蒸馏的收益递减
│
├─ 场景2: Teacher 模型不可用
│    GPT-4 API 无法做 logit-level 蒸馏
│    只能用 black-box 蒸馏，效果有限
│
├─ 场景3: 领域差异太大
│    Teacher 的训练数据和目标领域不同
│    蒸馏可能引入 Teacher 的偏差
│
├─ 场景4: 快速验证阶段
│    量化是"加一行的降成本"
│    蒸馏是"训练一个月的降成本"
│    先量化再蒸馏
```

### 1.5 蒸馏的边际收益递减

```
模型大小 vs 蒸馏收益的关系：

Teacher: GPT-4o级别 (>100B)

Student 大小      蒸馏收益      建议
─────────────────────────────────────
< 1B             低          直接量化+剪枝，蒸馏收益有限
1B-3B            中          轻量蒸馏 + QAT
3B-7B            高          标准蒸馏，收益最大
7B-20B           中          局部蒸馏（只蒸馏特定能力）
> 20B            低          直接量化部署，蒸馏性价比低

结论：蒸馏的 sweet spot 是 Teacher 比 Student 大 10-50x。
      差距太小 → 蒸馏收益低
      差距太大 → Student 学不动
```

## 2. 知识蒸馏方法论

### 2.1 蒸馏三要素

```
Teacher模型（大） ──→ 知识迁移 ──→ Student模型（小）
   ↑                      ↑
   ├── 软标签 (logits)     ├── 架构选择
   ├── 中间层特征          ├── 训练策略
   └── 关系知识            └── 损失函数设计
```

### 2.2 蒸馏类型对比

| 类型 | 监督信号 | 实现复杂度 | 效果 | 代表方法 |
|------|---------|-----------|------|---------|
| **Logit蒸馏** | Teacher输出概率分布 | 低 | ⭐⭐⭐ | DistilBERT, MiniLM |
| **特征蒸馏** | Teacher中间层表示 | 中 | ⭐⭐⭐⭐ | TinyBERT, MobileBERT |
| **关系蒸馏** | Teacher层间关系图谱 | 高 | ⭐⭐⭐⭐⭐ | PKD, RKD |
| **Self-Distillation** | 自身作为Teacher | 低 | ⭐⭐⭐ | 自蒸馏, 对比学习 |
| **黑盒蒸馏** | 仅通过API访问Teacher | 高 | ⭐⭐ | 离线数据生成蒸馏 |

### 2.3 Logit蒸馏原理

```
Teacher输出:  [0.1, 0.7, 0.05, 0.15]  (软概率分布，含类间关系信息)
Student输出:  [0.2, 0.5, 0.1, 0.2]
                  ↓
损失 = α × KL(Teacher || Student) + (1-α) × CrossEntropy(Student, 真实标签)

温度T控制软标签平滑度:
  T=1:  原始概率
  T=2-5: 软化分布 → 暴露更多类间关系
  T→∞:   均匀分布，无信息
```

### 2.4 蒸馏训练配置参考

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| 温度 T | 2-8 (分类) / 1-2 (生成) | NLP任务偏好较低温度 |
| α (蒸馏损失权重) | 0.5-0.9 | Teacher可靠时取高值 |
| 学习率 | Teacher lr × 0.1 | 蒸馏训练更稳定 |
| Batch size | 256-1024 | 尽可能大 |
| 训练数据 | 任务数据 + Teacher生成数据 | 数据质量比数量重要 |

## 3. 主流蒸馏方案

### 3.1 LLM蒸馏

| 方案 | Teacher→Student | 方法 | 能力保留 | 特点 |
|------|----------------|------|---------|------|
| DistilBERT | BERT→60%参数 | Logit蒸馏 | 97% | 推理速度×2 |
| TinyLLaMA | LLaMA→1.1B | 数据蒸馏+持续训练 | ~90% | 中文支持好 |
| DeepSeek-R1-Distill | R1→1.5B-70B | 推理轨迹蒸馏 | 95%+ | 保留推理能力 |
| Orca | GPT-4→LLaMA | 逐步蒸馏+解释追踪 | ~95% | 任务泛化性强 |
| Phi系列 | 合成数据训练 | 数据质量驱动 | — | 小模型高表现 |

### 3.2 多模态蒸馏

| 方案 | Teacher→Student | 模态 | 挑战 |
|------|----------------|------|------|
| ViT蒸馏 | ViT-H→ViT-B/S | 视觉 | 特征对齐维度差异大 |
| LLaVA蒸馏 | LLaVA-13B→7B | 视觉+语言 | 跨模态logits对齐 |
| CLIP蒸馏 | ViT-L→ViT-B | 图文对比 | 对比损失蒸馏复杂 |

### 3.3 蒸馏+量化联合

```
联合压缩 pipeline:

Step1: 大模型 (FP16) → Step2: 蒸馏瘦身 (FP16) → Step3: QAT量化 (INT4/INT8)
    参考性能:                        │                        │
    Mistral-7B                      Mistral-2.7B             Mistral-2.7B-INT4
    (100%)                          (~65%能力)              (~62%能力, 8x压缩)
```

## 4. 结构剪枝

### 4.1 剪枝粒度

| 类型 | 粒度 | 压缩比 | 硬件加速 | 实现难度 |
|------|------|--------|---------|---------|
| 非结构化剪枝 | 单个权重 | 高 | 低（稀疏矩阵支持有限） | 低 |
| 结构化剪枝 | 神经元/通道/注意力头 | 中 | 高（直接减少计算量） | 中 |
| 层剪枝 | 整个Transformer层 | 低 | 高 | 低 |

### 4.2 剪枝流程

```
1. 训练大模型 → 2. 评估重要性 → 3. 移除不重要结构 → 4. 微调恢复 → 5. 评估
                                    ↑
                重要性评估方法：
                ├── 权重幅值 (Magnitude)
                ├── 梯度×权重 (Movement)
                ├── 泰勒展开 (Taylor)
                └── 损失变化 (Loss-aware)
```

### 4.3 LLM结构化剪枝实践

| 剪枝目标 | 方法 | 参数量减少 | 速度提升 | 典型配置 |
|---------|------|-----------|---------|---------|
| Attention头剪枝 | 移除低注意力分数head | 10-20% | 15-25% | LLaMA-7B → 切掉12/32 heads |
| FFN中间层剪枝 | 移除低激活神经元 | 20-30% | 20-35% | 保留Top-50% FFN神经元 |
| 层剪枝 | 移除冗余层 | 10-33% | 10-30% | 移除最后4层常见 |
| 混合剪枝 | 多头+FFN+层联合 | 30-50% | 30-50% | SparseGPT / Wanda |

> **推荐工具**: SparseGPT、Wanda、LLM-Pruner

## 5. 架构搜索 (NAS)

### 5.1 NAS在蒸馏中的应用

```
搜索空间定义
├── Transformer层数: 12-24
├── 注意力头数: 8-16
├── FFN中间维度: 2048-8192
├── 隐藏层维度: 512-1024
└── 激活函数: ReLU / GELU / SwiGLU
        ↓
性能评估器 (Teacher辅助评估)
        ↓
搜索算法 (进化 / 贝叶斯 / 可微分)
        ↓
最优Student架构 → 蒸馏训练
```

### 5.2 ELegant 架构搜索原则

```
对架构师最实用的方法：

1. 固定深度，搜索宽度
   └─ 层数 = Teacher的1/2, 每层维度从Teacher降维

2. 固定宽度，搜索深度
   └─ 维度 = Teacher的1/2, 层数逐步增加

3. 知识继承
   └─ 直接复制Teacher前 N 层，后 M 层随机初始化
```

## 6. 生产级蒸馏决策框架

### 6.1 选型决策树

```
部署场景
├── 延迟敏感 (<100ms) → 蒸馏(2-4x) + 量化(INT4)
├── 内存受限 (<4GB)   → 蒸馏(10x+) + 剪枝 + 量化
├── 批量高吞吐        → 量化(INT4)优先，蒸馏其次
├── 领域专用任务      → 任务蒸馏 + PEFT (sFT/DPO)
└── 通用能力保留      → 黑盒蒸馏 + 数据合成
```

### 6.2 效果预估模板

| 指标 | Teacher | Student | 可接受阈值 | 验证方法 |
|------|---------|---------|-----------|---------|
| 准确率/EM | 92.5% | 89.1% | ≥ 90% | 标注测试集 |
| ROUGE-L | 0.45 | 0.42 | ≥ 0.42 | 参考摘要集 |
| 推理延迟 | 450ms | 85ms | ≤ 100ms | 压测 |
| 吞吐量 | 50 req/s | 320 req/s | ≥ 200 | 负载测试 |
| 显存占用 | 16GB | 2.8GB | ≤ 4GB | 监控 |

### 6.3 常见陷阱

| 陷阱 | 表现 | 原因 | 对策 |
|------|------|------|------|
| Teacher过强Student学不动 | Student能力远低于预期 | Teacher能力超出Student架构上限 | 选适中Teacher或用助教(Intermediate)蒸馏 |
| 蒸馏后领域偏移 | 通用任务能力下降 | 蒸馏数据分布偏 | 混合通用数据+领域数据 |
| 评估幻觉 | 基准测试得分高但生产效果差 | 测试集不匹配 | 建生产级测试集 |
| 联合压缩负协同 | D+Q+P效果差于单独压缩 | 各压缩方法互斥效应 | 优先蒸馏+量化组合 |
