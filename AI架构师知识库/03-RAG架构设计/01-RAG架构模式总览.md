# RAG架构模式总览

> 检索增强生成的9种架构模式详解

## 1. RAG基础概念

### 1.1 为什么需要RAG？

**大模型的三大局限：**
1. **知识时效性**：训练数据有截止日期
2. **幻觉问题**：生成看似合理但错误的内容
3. **领域知识不足**：对专业领域理解有限

**RAG的核心价值：**
- 提供实时、准确的知识来源
- 减少幻觉，提高可信度
- 支持领域定制化
- 可追溯答案来源

### 1.2 RAG基本流程

```
用户Query → 检索模块 → 相关文档 → 增强Prompt → LLM生成 → 带引用的答案
                ↑
           向量数据库
```

**三个核心组件：**
1. **索引（Indexing）**：文档处理与存储
2. **检索（Retrieval）**：查询相关文档
3. **生成（Generation）**：结合上下文生成答案

## 2. 九种RAG架构模式

### 2.1 Standard RAG（标准RAG）

**架构：**
```
Query → Embedding → 向量检索 → Top-K文档 → LLM生成
```

**特点：**
- 最简单直接的实现
- 单次检索，单次生成
- 适合：事实性问答、简单查询

**局限：**
- 检索质量直接影响生成质量
- 无法处理检索失败情况

---

### 2.2 Advanced RAG（高级RAG）

**改进点：**

**检索前优化：**
- **查询重写**：将用户Query改写为更适合检索的形式
- **查询扩展**：生成多个相关查询，扩大检索范围
- **HyDE（假设文档嵌入）**：生成假设答案，用其Embedding检索

**检索后优化：**
- **重排序（Rerank）**：使用Cross-encoder精排Top-K结果
- **上下文压缩**：压缩检索结果，保留关键信息
- **过滤**：基于元数据过滤不相关文档

**架构：**
```
Query → 查询重写 → 多路检索 → 重排序 → 上下文压缩 → LLM生成
```

---

### 2.3 Modular RAG（模块化RAG）

**核心思想：** 将RAG拆分为可插拔模块

**模块组成：**
```
┌─────────────────────────────────────┐
│           搜索模块                   │
│  (向量检索 + 关键词检索 + 知识图谱)   │
└─────────────┬───────────────────────┘
              ↓
┌─────────────────────────────────────┐
│           重排模块                   │
│  (粗排 + 精排 + 多样性重排)          │
└─────────────┬───────────────────────┘
              ↓
┌─────────────────────────────────────┐
│           生成模块                   │
│  (摘要 + 问答 + 多文档融合)          │
└─────────────────────────────────────┘
```

**优势：**
- 灵活组合不同策略
- 便于A/B测试和迭代
- 支持多场景复用

---

### 2.4 Corrective RAG（纠错RAG）

**核心思想：** 评估检索质量，低质量时触发补充检索

**流程：**
```
1. 初始检索Top-K文档
2. 评估检索相关性分数
3. 若分数 < 阈值:
   - 触发Web搜索补充
   - 或提示用户澄清
4. 综合生成答案
```

**评估方法：**
- **置信度评分**：检索分数分布
- **LLM评估**：用LLM判断文档相关性
- **规则判断**：关键词匹配度

**适用场景：** 开放域问答、检索质量不稳定

---

### 2.5 Self-RAG（自反思RAG）

**核心思想：** 模型自评估生成内容，决定是否需要检索

**特殊Token设计：**
```
[Retrieve] - 需要检索
[No Retrieve] - 无需检索
[IsRel] - 验证相关性
[IsSup] - 验证支持度
[IsUse] - 验证有用性
```

**流程：**
```
生成过程中:
→ 遇到[Retrieve] → 执行检索 → 继续生成
→ 遇到[IsRel] → 评估相关性 → 决定是否继续
→ 最终输出带引用和置信度的答案
```

**优势：**
- 动态决定检索时机
- 生成内容带自评估
- 可追溯推理过程

---

### 2.6 Adaptive RAG（自适应RAG）

**核心思想：** 根据问题复杂度动态选择检索策略

**复杂度分类：**
| 复杂度 | 策略 | 示例 |
|--------|------|------|
| 简单 | 直接生成，无需检索 | "你好"、"谢谢" |
| 中等 | 单次RAG | 事实性查询 |
| 复杂 | 迭代RAG + 多跳推理 | 多条件分析 |

**决策模型：**
```
Query → 分类器 → 选择策略 → 执行
          ↑
    基于问题长度、关键词、历史数据
```

**实现方式：**
- 轻量级分类器（BERT等）
- LLM自我判断
- 规则引擎

---

### 2.7 GraphRAG（图RAG）

**核心思想：** 结合知识图谱进行多跳推理

**架构：**
```
文档 → 实体抽取 → 关系抽取 → 知识图谱构建
                                    ↓
Query → 实体识别 → 图谱检索（多跳）→ 子图 → LLM生成
```

**优势：**
- 处理复杂关系推理
- 支持多跳问答
- 结构化知识表示

**技术栈：**
- 图数据库：Neo4j、NebulaGraph
- 向量+图混合：将子图向量化后检索

**适用场景：** 医学、法律、金融等关系密集型领域

---

### 2.8 Multi-Modal RAG（多模态RAG）

**核心思想：** 支持文本、图像、音频、视频等多种模态

**架构：**
```
┌─────────────┐  ┌─────────────┐  ┌─────────────┐
│   文本      │  │   图像      │  │   音频      │
│  Embedding  │  │  CLIP/ViT   │  │  Whisper    │
└──────┬──────┘  └──────┬──────┘  └──────┬──────┘
       └─────────────────┼─────────────────┘
                         ↓
              ┌─────────────────┐
              │   统一向量空间   │
              └────────┬────────┘
                       ↓
              ┌─────────────────┐
              │   多模态检索     │
              └────────┬────────┘
                       ↓
              ┌─────────────────┐
              │  多模态LLM生成   │
              └─────────────────┘
```

**应用场景：**
- 图文混合问答
- 视频内容检索
- 产品多模态搜索

---

### 2.9 Agentic RAG（Agent化RAG）

**核心思想：** 将RAG作为Agent的工具，支持复杂任务分解

**架构：**
```
用户请求 → Agent规划 → 工具调用循环 → 综合答案
              ↓
    ┌─────────┼─────────┐
    ↓         ↓         ↓
  检索工具   计算工具   其他API
  (RAG)     (Calculator) (Search)
```

**ReAct模式：**
```
Thought: 我需要查询2024年GDP数据
Action: 检索工具(query="2024年中国GDP")
Observation: 检索到相关文档...
Thought: 现在我需要计算增长率
Action: 计算工具(expression="(134.9-126)/126*100")
...
```

**优势：**
- 处理复杂多步任务
- 工具组合使用
- 推理过程透明

## 3. RAG架构选型指南

### 3.1 选型决策树

```
数据类型?
├── 结构化关系数据
│   └── GraphRAG
├── 多模态数据
│   └── Multi-Modal RAG
└── 非结构化文本
    ├── 需要复杂推理?
    │   ├── 是 → Agentic RAG
    │   └── 否 → 继续判断
    ├── 检索质量不稳定?
    │   ├── 是 → Corrective RAG
    │   └── 否 → 继续判断
    ├── 问题复杂度差异大?
    │   ├── 是 → Adaptive RAG
    │   └── 否 → 继续判断
    ├── 需要自评估?
    │   ├── 是 → Self-RAG
    │   └── 否 → Advanced RAG / Standard RAG
    └── 需要模块化扩展?
        ├── 是 → Modular RAG
        └── 否 → Standard RAG
```

### 3.2 场景匹配表

| 场景 | 推荐模式 | 理由 |
|------|----------|------|
| 企业知识库 | Advanced RAG | 平衡效果与复杂度 |
| 开放域问答 | Corrective RAG | 补充外部知识 |
| 科研文献 | GraphRAG | 复杂引用关系 |
| 客服机器人 | Adaptive RAG | 问题复杂度不一 |
| 智能助手 | Agentic RAG | 支持复杂任务 |
| 电商搜索 | Multi-Modal RAG | 图文混合 |
| 法律分析 | Self-RAG | 高可信度要求 |

## 4. RAG评估体系

### 4.1 检索质量指标

| 指标 | 说明 | 计算方式 |
|------|------|----------|
| **Hit Rate** | Top-K命中率 | 正确答案在Top-K中的比例 |
| **MRR** | 平均倒数排名 | 1/rank的平均值 |
| **NDCG** | 归一化折损累积增益 | 考虑排序质量的指标 |
| **Precision@K** | Top-K精确率 | 相关文档/总文档 |
| **Recall@K** | Top-K召回率 | 检索到的相关文档/总相关文档 |

### 4.2 生成质量指标

| 指标 | 说明 | 评估方式 |
|------|------|----------|
| **Faithfulness** | 忠实度 | 答案是否基于检索内容 |
| **Answer Relevance** | 答案相关性 | 是否回答用户问题 |
| **Context Precision** | 上下文精确率 | 检索内容是否相关 |
| **Context Recall** | 上下文召回率 | 是否检索到必要信息 |
| **Answer Correctness** | 答案正确性 | 与标准答案对比 |

### 4.3 评估工具

**RAGAS：**
```python
from ragas import evaluate
from ragas.metrics import faithfulness, answer_relevancy

result = evaluate(
    dataset=eval_dataset,
    metrics=[faithfulness, answer_relevancy]
)
```

**TruLens：**
- 提供反馈函数（Feedback Functions）
- 支持自定义评估逻辑
- 与LangChain/LlamaIndex集成

## 5. 架构师最佳实践

### 5.1 RAG实施Checklist

**索引阶段：**
- [ ] 选择合适的分块策略（固定长度/语义/递归）
- [ ] 设计元数据字段（时间、来源、类别等）
- [ ] 配置Embedding模型（考虑多语言）
- [ ] 建立索引更新机制

**检索阶段：**
- [ ] 实现混合检索（向量+关键词）
- [ ] 配置重排序模型
- [ ] 设置合理的Top-K值
- [ ] 实现查询重写/扩展

**生成阶段：**
- [ ] 设计Prompt模板（包含引用格式）
- [ ] 配置上下文窗口管理
- [ ] 实现答案后处理（格式化、校验）
- [ ] 添加来源引用

### 5.2 常见陷阱

**陷阱1：分块过大或过小**
- 过大：噪声多，检索不精确
- 过小：丢失上下文，语义不完整
- 建议：256-512 tokens，根据内容调整

**陷阱2：忽视元数据过滤**
- 问题：检索到过期或不相关内容
- 解决：利用元数据预过滤

**陷阱3：缺少重排序**
- 问题：向量检索Top-K质量不稳定
- 解决：添加Cross-encoder精排

**陷阱4：Prompt工程不足**
- 问题：模型不利用检索内容
- 解决：明确指令+示例Few-shot

### 5.3 性能优化

**索引优化：**
- 增量更新而非全量重建
- 分层索引（热数据/冷数据）
- 多副本负载均衡

**检索优化：**
- 向量量化（IVF、HNSW）
- 缓存热门查询
- 并行检索

**生成优化：**
- 流式输出
- 上下文压缩
- 投机解码
