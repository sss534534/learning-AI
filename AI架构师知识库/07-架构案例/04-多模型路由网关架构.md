# 案例四：多模型路由网关架构

> 统一管理多个LLM供应商，智能路由降低成本50%+

## 1. 项目背景

### 1.1 业务需求

**场景：** 中大型企业，多个业务线使用不同LLM

**痛点：**
- 各业务线独立对接LLM供应商，重复建设
- 无法统一监控Token用量和成本
- 模型故障时缺乏自动切换能力
- 不同任务使用相同模型，成本浪费

**目标：**
- 统一LLM接入层，屏蔽供应商差异
- 智能路由：根据任务自动选择最优模型
- 成本优化：在保证质量前提下降低50%+成本
- 高可用：自动故障转移

### 1.2 接入模型

| 供应商 | 模型 | 用途 | 单价（每1M Token） |
|--------|------|------|---------------------|
| OpenAI | GPT-4o | 复杂推理 | $5/$15 |
| OpenAI | GPT-4o-mini | 简单任务 | $0.15/$0.6 |
| Anthropic | Claude-3.5 | 长文本 | $3/$15 |
| 阿里云 | Qwen-Max | 中文任务 | ¥40/¥120 |
| 阿里云 | Qwen-Plus | 通用任务 | ¥8/¥24 |
| DeepSeek | DeepSeek-V3 | 高性价比 | ¥2/¥8 |
| 自部署 | Qwen-72B | 敏感数据 | 仅硬件成本 |

### 2.2 核心设计原则

| 原则 | 说明 |
|------|------|
| **统一接口** | 业务方只需对接一个API，不关心后端模型 |
| **智能路由** | 根据任务特征自动选择最优模型 |
| **透明可观测** | 全链路追踪，每次请求可查路由决策 |
| **高可用** | 自动故障转移，业务无感知 |
| **成本可控** | 预算管理+成本优化策略 |

### 4.1 路由策略

**策略1：规则路由**
```python
RULES = [
    # 敏感数据 → 自部署模型
    {"condition": "contains_sensitive_data", "target": "self-hosted-qwen-72b"},
    
    # 简单分类 → 便宜模型
    {"condition": "task == 'classification'", "target": "qwen-plus"},

    {"condition": "task == 'code_generation'", "target": "deepseek-v3"},
    
    # 高优先级 → GPT-4o
    {"condition": "priority == 'high'", "target": "gpt-4o"},
]
```

**策略2：成本优化路由**
```python
class CostOptimizedRouter:
    """成本优先路由"""
    
    def route(self, request):
        candidates = self._get_available_models(request)
        
        # 按成本排序
        candidates.sort(key=lambda m: self._estimate_cost(m, request))
        
        # 选择满足质量要求的最低成本模型
        for model in candidates:
            if self._meets_quality_floor(model, request):
                return model
        
        # 兜底：最强模型
        return "gpt-4o"
    
    def _estimate_cost(self, model, request):
        pricing = MODEL_PRICING[model]
        input_cost = request.input_tokens * pricing.input_per_1m / 1_000_000
        output_cost = request.output_tokens * pricing.output_per_1m / 1_000_000
        return input_cost + output_cost
```

**策略3：质量优先路由**
```python
class QualityOptimizedRouter:
    """质量优先路由"""
    
    # 模型质量排名（基于历史评估数据）
    QUALITY_RANKING = {
        "gpt-4o": 0.95,
        "claude-3-5": 0.93,
        "qwen-max": 0.90,
        "deepseek-v3": 0.88,
        "qwen-plus": 0.82,
        "gpt-4o-mini": 0.78,
    }
    
    def route(self, request):
        if request.constraints.get("quality_floor", 0) >= 0.9:
            return "gpt-4o"
        
        # 在满足成本约束下选择质量最高的
        candidates = self._filter_by_cost(request)
        candidates.sort(key=lambda m: self.QUALITY_RANKING[m], reverse=True)
        return candidates[0]
```

**策略4：延迟敏感路由**
```python
class LatencyAwareRouter:
    """延迟感知路由"""
    
    def route(self, request):
        max_latency = request.constraints.get("max_latency_ms", 5000)
        
        # 选择历史P99延迟满足要求的模型
        candidates = [
            m for m in self.available_models
            if self.latency_stats[m].p99 < max_latency
        ]
        
        if not candidates:
            # 放宽到P95
            candidates = [
                m for m in self.available_models
                if self.latency_stats[m].p95 < max_latency
            ]
        
        return candidates[0] if candidates else "gpt-4o"
```

## 5. 高可用设计

### 5.1 故障转移

```python
class FailoverManager:
    """故障转移管理"""
    
    def __init__(self):
        self.circuit_breakers = {}  # 熔断器
        self.fallback_chain = {
            "gpt-4o": ["claude-3-5", "qwen-max"],
            "claude-3-5": ["gpt-4o", "qwen-max"],
            "qwen-max": ["gpt-4o", "claude-3-5"],
            "deepseek-v3": ["qwen-plus", "gpt-4o-mini"],
        }
    
    async def call_with_failover(self, request):
        primary = self.router.route(request)
        fallbacks = self.fallback_chain.get(primary, ["gpt-4o"])
        
        # 尝试主模型
        if not self._is_circuit_open(primary):
            try:
                return await self._call_model(primary, request, timeout=5)
            except (TimeoutError, APIError) as e:
                self._record_failure(primary, e)
        
        # 尝试备选模型
        for fallback in fallbacks:
            if not self._is_circuit_open(fallback):
                try:
                    result = await self._call_model(fallback, request, timeout=8)
                    self._log_failover(primary, fallback)
                    return result
                except:
                    continue
        
        raise AllModelsUnavailableError()
```

### 5.2 熔断器

```python
class CircuitBreaker:
    """熔断器"""
    
    def __init__(self, failure_threshold=5, recovery_timeout=60):
        self.failure_count = 0
        self.failure_threshold = failure_threshold
        self.recovery_timeout = recovery_timeout
        self.state = "closed"  # closed / open / half_open
        self.last_failure_time = None
    
    def is_open(self):
        if self.state == "open":
            # 检查是否恢复
            if time.time() - self.last_failure_time > self.recovery_timeout:
                self.state = "half_open"
                return False
            return True
        return False
    
    def record_success(self):
        self.failure_count = 0
        self.state = "closed"
    
    def record_failure(self):
        self.failure_count += 1
        self.last_failure_time = time.time()
        if self.failure_count >= self.failure_threshold:
            self.state = "open"
```

## 6. 成本管理

### 6.1 预算管理

```python
class BudgetManager:
    """预算管理"""
    
    def __init__(self):
        # 按业务线设置月度预算
        self.budgets = {
            "customer_service": {"monthly": 50000, "used": 0},
            "knowledge_base": {"monthly": 30000, "used": 0},
            "code_assistant": {"monthly": 20000, "used": 0},
        }
    
    def check_budget(self, business, estimated_cost):
        """检查预算"""
        budget = self.budgets[business]
        remaining = budget["monthly"] - budget["used"]
        
        if remaining < estimated_cost:
            # 预算不足，降级到便宜模型
            return {"allowed": False, "fallback_model": "gpt-4o-mini"}
        
        return {"allowed": True}
    
    def record_usage(self, business, cost):
        """记录使用量"""
        self.budgets[business]["used"] += cost
```

## 8. 经验总结

### 8.1 关键成功因素

1. **统一接口是基础**：屏蔽供应商差异，业务方零改动切换模型
2. **路由策略要可配置**：不同业务线需求不同，不能一刀切
3. **成本可视化**：实时成本数据是推动优化的动力
4. **故障转移要快**：熔断+自动切换，业务无感知
5. **渐进式迁移**：先旁路运行验证，再逐步切换流量

### 8.2 踩过的坑

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 路由决策不合理 | 规则过于简单 | 多策略组合+历史数据驱动 |
| 供应商API变更 | 未做版本管理 | 适配器模式+版本锁定 |
| 成本超预算 | 缺少预算控制 | 添加预算管理+告警 |
| 故障转移级联 | 所有请求涌向备选 | 熔断器+限流 |
