# AI平台与多租户架构

> 从单租户Demo到企业级AI平台：租户隔离、配额管理、计费体系完整架构

## 一、AI平台的架构演进

### 1.1 三个层次

```
Level 1: 模型即服务 (Model-as-a-Service)
  → 提供统一的模型API,多租户共享推理资源
  → 代表: OpenAI API, Anthropic API, 通义千问API

Level 2: AI平台 (AI Platform)
  → 模型API + 微调 + RAG + Agent + 评估 + 监控
  → 代表: Azure AI Foundry, Google Vertex AI, Dify

Level 3: AI基础设施平台 (AI Infra Platform)  
  → GPU集群 + 训练 + 推理 + 存储 + 网络
  → 代表: NVIDIA DGX Cloud, CoreWeave, Lambda
```

### 1.2 本文聚焦 Level 1+2

典型内部AI平台（面向企业内部开发者的LLM网关+工具平台）。

## 二、多租户隔离策略

### 2.1 隔离级别对比

| 级别 | 方案 | 隔离强度 | 资源利用率 | 成本 | 适用 |
|------|------|---------|-----------|------|------|
| **物理隔离** | 独立GPU/集群 | ★★★★★ | 低(30-50%) | 高 | 金融/医疗 |
| **容器隔离** | 独立容器+PVC | ★★★★ | 中(50-70%) | 中 | 企业 |
| **命名空间隔离** | K8s Namespace | ★★★ | 中高(60-80%) | 中低 | 中型团队 |
| **逻辑隔离** | API Key + 配额 | ★★ | 高(80-95%) | 低 | SaaS/自用 |
| **无隔离** | 共享一切 | ★ | 最高(90%+) | 最低 | 内部工具 |

### 2.2 混合隔离架构（推荐）

```
租户分级:

Tier-0: VIP租户 (金融、政府)
  → 物理隔离: 独立GPU节点池
  → 独立VPC, 独立存储卷
  → 专用网络通道

Tier-1: 企业租户
  → 容器隔离: 独立K8s Namespace
  → 共享GPU池但独立推理实例
  → 独立数据卷

Tier-2: 标准租户
  → 逻辑隔离: API Key + 配额
  → 共享推理实例 (Continuous Batching)
  → 数据逻辑隔离 (tenant_id标签)

Tier-3: 免费/试用租户
  → 逻辑隔离, 严格配额
  → 共享资源, 低优先级
  → 数据隔离, 7天自动清理
```

### 2.3 租户上下文传播

```python
# 全链路租户上下文
import contextvars

tenant_ctx = contextvars.ContextVar('tenant_id')

class TenantMiddleware:
    async def __call__(self, request, call_next):
        # 从API Key解析租户
        api_key = request.headers.get("X-API-Key")
        tenant = await self.resolve_tenant(api_key)
        
        # 注入上下文
        token = tenant_ctx.set(tenant.id)
        
        # 添加租户标签到所有日志/metrics
        request.state.tenant_id = tenant.id
        request.state.tenant_tier = tenant.tier
        
        response = await call_next(request)
        tenant_ctx.reset(token)
        return response

# 模型服务感知租户
class TenantAwareModelService:
    async def generate(self, prompt, tenant_id, tier):
        # Tier-0: 路由到独立实例
        if tier == "vip":
            return await self.vip_pool.generate(prompt)
        
        # Tier-1/2: 共享池, 但限制资源
        return await self.shared_pool.generate(
            prompt,
            max_concurrency=self.get_quota(tenant_id, "concurrency")
        )
```

### 3.1 多维度配额模型

```python
class TenantQuota:
    """租户配额定义"""
    tenant_id: str
    
    # Token维度
    max_tokens_per_minute: int    # TPM限制
    max_tokens_per_day: int       # TPD限制
```

### 3.2 分布式限流实现

```python
# 令牌桶 + Redis 分布式限流
import asyncio
import redis.asyncio as redis
import time

class DistributedRateLimiter:
    def __init__(self, redis_client: redis.Redis):
        self.redis = redis_client
    
    async def check_and_consume(
        self, tenant_id: str, tokens: int, 
        max_tpm: int, window_seconds: int = 60
    ) -> bool:
        """滑动窗口限流"""
        key = f"ratelimit:{tenant_id}:tpm"
        now = time.time() * 1000  # ms
        
        # Lua脚本: 原子操作
        lua_script = """
        local key = KEYS[1]
        local now = tonumber(ARGV[1])
        local window = tonumber(ARGV[2]) * 1000
        local tokens = tonumber(ARGV[3])
        local max_tpm = tonumber(ARGV[4])
        
        -- 移除过期条目
        redis.call('ZREMRANGEBYSCORE', key, 0, now - window)
        
        -- 计算当前使用量
        local current = 0
        local members = redis.call('ZRANGEBYSCORE', key, now - window, now, 'WITHSCORES')
        for i = 1, #members, 2 do
            current = current + members[i + 1]
        end
        
        -- 检查是否超限
        if current + tokens > max_tpm then
            return 0
        end
        
        -- 记录消费
        redis.call('ZADD', key, tokens, now)
        redis.call('EXPIRE', key, window * 2)
        return 1
        """
        
        result = await self.redis.eval(
            lua_script, 1, key, now, window_seconds, tokens, max_tpm
        )
        return result == 1
```

### 3.3 多级限流策略

```
Level 1: 全局限流 (平台级)
  → 防止整个平台过载
  → 配置: 全局最大 TPM

Level 2: 租户限流 (租户级)
  → 保证租户间公平
  → 配置: 每个租户的 TPM/RPM

Level 3: 用户限流 (用户级)
  → 租户内用户隔离
  → 配置: 每个用户的 TPM

Level 4: 模型限流 (模型级)  
  → 保护特定模型不过载
  → 配置: 每个模型的 TPM

限流响应:
  - reject: 返回 429 Too Many Requests
  - queue: 加入优先级队列等待
  - degrade: 降级到更小/更便宜的模型
```

### 4.2 统一LLM Gateway

```python
# 多模型统一代理
from typing import AsyncIterator
import httpx

class LLMGateway:
    def __init__(self):
        self.backends = {
            "openai": OpenAIBackend(),
            "anthropic": AnthropicBackend(),
            "qwen": QwenBackend(),
            "deepseek": DeepSeekBackend(),
        }
    
    async def chat_completion(
        self, 
        messages: list,
        model: str,
        tenant_id: str,
        stream: bool = False
    ):
        # 1. 认证 & 授权
        tenant = await self.auth_middleware(tenant_id)
        
        # 2. 配额检查
        if not await self.rate_limiter.check(tenant_id, model):
            raise HTTPException(429, "Rate limit exceeded")
        
        # 3. 模型路由
        backend, actual_model = self.route(model, tenant.tier)
        
        # 4. Prompt安全审核 (异步)
        asyncio.create_task(self.content_safety.check(messages, tenant_id))
        
        # 5. 语义缓存检查
        cached = await self.semantic_cache.get(messages, model)
        if cached:
            return cached
        
        # 6. 调用后端
        response = await backend.chat(messages, actual_model, stream)
        
        # 7. 计量 & 计费
        await self.metering.record(tenant_id, model, response.usage)
        
        # 8. 日志记录
        await self.audit_log.log(tenant_id, model, messages, response)
        
        return response
```

```python
class SmartRouter:
    """基于任务类型+成本+延迟的智能路由"""
    
    async def route(self, messages: list, tenant_tier: str) -> tuple:
        task_type = self.classify(messages)
        
        routing_table = {
            "coding": {
                "vip": ("deepseek", "deepseek-coder-v2"),

                "free": ("qwen", "qwen2.5-coder-1.5b"),

            },

                "standard": ("qwen", "qwen2.5-14b"),

            },
```

## 五、计费与成本体系

### 5.1 计费模型

| 模型 | 适用 | 优势 | 劣势 |
|------|------|------|------|
| **按量付费 (Pay-as-you-go)** | 不确定用量 | 灵活 | 成本不可预测 |
| **预付费包 (Prepaid)** | 稳定用量 | 折扣(20-50%) | 资金占用 |
| **订阅制 (Subscription)** | 固定用量 | 可预测 | 超额限制 |
| **混合 (Hybrid)** | 企业 | 兼顾灵活和成本 | 复杂 |

### 5.2 实时计费引擎

```python
class BillingEngine:
    # 定价表 (每1K tokens)
    pricing = {
        "gpt-4o": {"input": 0.0025, "output": 0.01},
        "gpt-4o-mini": {"input": 0.00015, "output": 0.0006},
        "claude-sonnet-4": {"input": 0.003, "output": 0.015},
        "deepseek-chat": {"input": 0.00014, "output": 0.00028},
        "qwen2.5-72b": {"input": 0.0005, "output": 0.002},
    }
    
    def calculate_cost(self, model: str, usage: dict) -> float:
        p = self.pricing[model]
        return (
            usage["prompt_tokens"] * p["input"] / 1000 +
            usage["completion_tokens"] * p["output"] / 1000
        )
    
    async def check_budget(
        self, tenant_id: str, model: str, estimated_tokens: int
    ) -> bool:
        """预算控制"""
        daily_spend = await self.get_daily_spend(tenant_id)
        monthly_budget = await self.get_monthly_budget(tenant_id)
        
        estimated_cost = self.calculate_cost(model, {
            "prompt_tokens": estimated_tokens,
            "completion_tokens": estimated_tokens  # 估算
        })
        
        if daily_spend + estimated_cost > monthly_budget / 30:
            return False
        
        return True
```

## 九、架构决策指南

```
设计你的AI平台时问自己:

1. 租户数量级?
   <10  → 物理/容器隔离
   10-100 → 逻辑隔离 (命名空间)
   >100 → API Key + 配额, 共享资源

2. 数据敏感性?
   高 (金融/医疗) → 物理隔离, 独立VPC
   中 (企业内部) → 逻辑隔离, 加密
   低 (公开) → 共享, 仅配额限制

3. 模型多样性?
   单一模型 → 简单网关
   多模型 → 智能路由 + 统一API
    
4. 计费需求?
   否 → 纯配额管理
   是 → 实时计费 + 预算控制
    
5. 隔离粒度?
   团队级 → API Key
   用户级 → API Key + 用户token
   应用级 → API Key + app_id
```
