# AI数据治理与隐私工程

> 训练数据不是越多越好——治理是AI系统的第一道防线

## 一、为什么AI数据治理至关重要

### 1.1 三大驱动力

| 驱动力 | 核心问题 | 风险 |
|--------|---------|------|
| **合规** | GDPR/PIPL/《数据安全法》 | 罚款最高全球营收4% |
| **质量** | Garbage In, Garbage Out | 模型输出不可靠 |
| **伦理** | 偏见、毒性、版权 | 品牌声誉损害、法律诉讼 |

### 1.2 数据即负债

```
数据量 ≠ 数据价值

未治理的数据:
  - 隐私泄露风险 (PII/PHI)
  - 版权侵权风险 (训练数据来源不明)
  - 偏见放大风险 (数据分布失衡)
  - 数据投毒风险 (恶意注入)
  
治理良好的数据:
  - 来源可追溯 (Data Lineage)
  - 质量可度量 (Quality Score)
  - 隐私可证明 (差分隐私)
  - 版本可回滚 (DVC/LakeFS)
```

## 二、训练数据版本管理

### 2.1 DVC (Data Version Control)

```bash
# DVC 工作流
dvc init
dvc remote add -d myremote s3://my-bucket/dvc-store

# 添加数据
dvc add data/train.jsonl
git add data/train.jsonl.dvc .gitignore
git commit -m "Add training data v1"

# 版本切换
git checkout v1-data
dvc checkout  # 恢复对应版本的数据

# 数据流水线
dvc stage add -n preprocess \
  -d raw_data/ -o processed/ \
  python preprocess.py

dvc repro  # 自动检测变化并重新运行
```

### 2.2 LakeFS：数据湖的 Git

```
LakeFS 核心概念:
  Branch: 数据分支 (类似Git branch)
  Commit: 不可变快照
  Merge: 合并数据变更
  Tag: 发布版本标签

AI训练工作流:
  main branch (生产数据)
    ├── experiment-A (加新数据)
    ├── experiment-B (数据清洗)
    └── experiment-C (数据增强)
  
  → 验证后 merge 到 main
```

```python
# LakeFS Python SDK
import lakefs

# 创建数据分支
lakefs.branch("training-data", "exp-add-chinese").create()

# 在分支上读写
client = lakefs.Client()
with client.branch("exp-add-chinese"):
    # 写入新数据不影响main
    df.to_parquet("lakefs://training-data/exp-add-chinese/data.parquet")

# 提交
client.commit("exp-add-chinese", message="Add Chinese corpus 50GB")

# 直接比较两个版本的差异
diff = client.diff("main", "exp-add-chinese")
print(f"Added: {diff.added}, Removed: {diff.removed}")

# 合并
client.merge("exp-add-chinese", into="main")
```

## 四、PII/隐私数据检测与脱敏

### 4.1 检测流水线

```python
# Presidio: Microsoft开源PII检测
from presidio_analyzer import AnalyzerEngine
from presidio_anonymizer import AnonymizerEngine

analyzer = AnalyzerEngine()
anonymizer = AnonymizerEngine()

text = "张三的身份证号是110101199001011234，电话13812345678"

# 检测
results = analyzer.analyze(
    text=text,
    entities=["PERSON", "CN_ID_CARD", "PHONE_NUMBER"],
    language="zh"
)

# 脱敏
anonymized = anonymizer.anonymize(
    text=text,
    analyzer_results=results,
    operators={
        "PERSON": {"type": "replace", "new_value": "[姓名]"},
        "CN_ID_CARD": {"type": "mask", "masking_char": "*", 
                         "chars_to_mask": 12, "from_end": True},
        "PHONE_NUMBER": {"type": "mask", "masking_char": "*",
                          "chars_to_mask": 8, "from_end": True}
    }
)
# 输出: "[姓名]的身份证号是110101********1234，电话138********"
```

### 4.2 多层级脱敏策略

```
Level 0: 无脱敏 (仅内部研究)
  → 需要明确授权
  
Level 1: 标签替换 (PII → `[PERSON]`, `[LOCATION]`)
  → 保留语义结构,损失部分信息
  
Level 2: 合成替换 (PII → 合成数据)
  → 用SDG生成仿真PII替代真实数据
  
Level 3: 差分隐私 (添加噪声)
  → 数学保证隐私,可验证
  
Level 4: 完全移除
  → 最大隐私保护,数据质量损失最大
```

### 4.3 大规模数据扫描

```python
# Spark + Presidio 分布式检测
from pyspark.sql import SparkSession
from presidio_analyzer import AnalyzerEngine

spark = SparkSession.builder.appName("PII-Scan").getOrCreate()

@spark.udf
def detect_pii(text):
    if text is None:
        return []
    analyzer = AnalyzerEngine()
    results = analyzer.analyze(text=text, language="zh")
    return [r.entity_type for r in results]

# 扫描TB级数据集
df = spark.read.parquet("s3://data-lake/corpus/")
pii_report = df.withColumn("pii_types", detect_pii("text"))

# 统计
pii_report.groupBy("pii_types").count().show()
# +------------------+---------+
# |pii_types         |count    |
# +------------------+---------+
# |[PERSON, PHONE]   |2,345,678|
# |[EMAIL]           |890,123  |
# |[]                |9.8B     |
# +------------------+---------+
```

## 五、差分隐私训练

### 5.1 DP-SGD 原理

```
传统SGD:   θ = θ - η·∇L(x)
DP-SGD:    θ = θ - η·(clip(∇L(x), C) + N(0, σ²C²I))

关键参数:
  ε (epsilon): 隐私预算,越小越隐私 (ε < 1 强隐私, ε < 10 实践中可接受)
  δ (delta): 失败概率,通常 1e-5 ~ 1e-6
  C: 梯度裁剪阈值
  σ: 噪声乘数
  
隐私损失: (ε, δ)-DP 保证
```

### 5.2 Opacus 实战

```python
from opacus import PrivacyEngine
from torch.utils.data import DataLoader

model = GPT2LMHeadModel.from_pretrained("gpt2")
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-4)

# 附加隐私引擎
privacy_engine = PrivacyEngine()
model, optimizer, data_loader = privacy_engine.make_private(
    module=model,
    optimizer=optimizer,
    data_loader=data_loader,
    noise_multiplier=1.0,   # σ, 噪声强度
    max_grad_norm=1.0,      # C, 裁剪阈值
)

# 正常训练循环
for epoch in range(epochs):
    for batch in data_loader:
        optimizer.zero_grad()
        loss = model(**batch).loss
        loss.backward()
        optimizer.step()

# 检查隐私消耗
epsilon = privacy_engine.get_epsilon(delta=1e-5)
print(f"用了 ε={epsilon:.2f} 的隐私预算")
# 输出: 用了 ε=4.32 的隐私预算

if epsilon > target_epsilon:
    print("⚠️ 隐私预算耗尽,停止训练!")
    break
```

### 5.3 差分隐私的代价

| ε值 | 隐私强度 | 模型质量 | 训练时间(额外) | 适用场景 |
|-----|---------|---------|--------------|---------|
| 0.1 | 极强 | 显著下降(-10~15%) | 3-5x | 医疗/金融 |
| 1.0 | 强 | 轻微下降(-3~5%) | 2-3x | 企业内部 |
| 8.0 | 中等 | 微弱(-1~2%) | 1.5-2x | 通用场景 |
| ∞ | 无隐私 | 基准 | 1x | 公开数据 |

## 六、合成数据治理

### 6.1 合成数据风险

```
合成数据的双重性:

正面:
  ✓ 避免真实PII泄露
  ✓ 缓解数据稀缺
  ✓ 平衡类别分布

风险:
  ✗ 可能记忆训练数据 (Membership Inference)
  ✗ 分布偏移 (Generated ≠ Real Distribution)
  ✗ 放大偏见 (Generator的偏见→合成数据→下游模型)
  ✗ 质量塌缩 (递归训练导致质量下降)
```

### 6.2 合成数据质量标准

```python
# SDMetrics: 合成数据质量评估
from sdmetrics.single_table import (
    DiagnosticReport,
    QualityReport
)
from sdv.evaluation.single_table import evaluate_quality

# 诊断: 检查基本有效性
diagnostic = DiagnosticReport()
diagnostic.generate(real_data, synthetic_data, metadata)

# 质量: 列形状 + 列对趋势
quality = QualityReport()
quality.generate(real_data, synthetic_data, metadata)

print(f"Overall Quality Score: {quality.get_score():.2%}")
# 期望 > 80%

# 详细指标
for prop, score in quality.get_properties().items():
    print(f"  {prop}: {score:.2%}")
```

### 6.3 合成数据使用政策

```
必须记录:
  1. 生成方法 (GAN/VAE/Diffusion/LLM)
  2. 生成器训练数据来源
  3. 质量评分 (与真实数据对比)
  4. 隐私评估 (是否记忆训练数据)
  5. 下游客群 (哪些模型使用了此数据)

禁止:
  ✗ 合成数据替代真实评测数据
  ✗ 无限递归训练 (A→合成B→训练C→合成D→...)
  ✗ 未经审计的合成数据用于关键领域
```

## 七、数据质量框架

### 7.1 多维质量评分

```python
# 数据质量评分卡
quality_card = {
    "completeness": {  # 完整性
        "null_rate": 0.02,      # 空值率 < 5%
        "truncation_rate": 0.001 # 截断率 < 1%
    },
    "accuracy": {       # 准确性
        "language_score": 0.95,   # 语言检测信心
        "factual_score": 0.88,    # 事实性 (NER+知识库)
        "grammar_score": 0.92     # 语法正确率
    },
    "consistency": {    # 一致性
        "format_consistency": 0.99, # 格式统一
        "schema_conformance": 1.0   # Schema符合
    },
    "timeliness": {     # 时效性
        "median_age_days": 180,
        "stale_rate": 0.15,       # 过期数据 (>2年)
    },
    "uniqueness": {     # 唯一性
        "near_dup_rate": 0.08,    # MinHash/LSH去重
        "exact_dup_rate": 0.03
    },
    "safety": {         # 安全性
        "toxic_rate": 0.001,      # 毒性检测
        "pii_rate": 0.02,         # PII泄漏率
        "bias_score": 0.15        # 偏见评分 (<0.2)
    }
}

overall_score = weighted_average(quality_card)
# 目标: > 0.85 (85分)
```

### 7.2 自动化质量流水线

```yaml

## 八、合规框架映射

### 8.1 主要法规要求

| 法规 | 关键要求 | AI数据影响 |
|------|---------|-----------|
| **GDPR** (EU) | 被遗忘权、数据可携、最小化 | 训练数据需支持删除 |
| **PIPL** (中国) | 知情同意、跨境评估、算法备案 | 数据出境需安全评估 |
| **AI Act** (EU) | 高风险AI技术文档、CE标志 | 训练数据来源记录 |
| **CCPA** (美国加州) | 消费者知情权、退出权 | 训练数据含加州居民信息需告知 |
| **HIPAA** (美国医疗) | PHI保护 | 医疗数据严格脱敏 |

### 8.2 数据跨境传输架构

```
中国境内                   境外
┌──────────┐          ┌──────────┐
│ 原始用户数据│ 安全评估  │ 脱敏后数据  │
│ (PII)     │ ──────→ │ (Anonymized)│
│           │  审批    │           │
└──────────┘          └──────────┘
      │                     │
      │                     ↓
┌──────────┐          ┌──────────┐
│ 境内训练   │          │ 全球训练   │
│ (境内GPU) │          │ (境外GPU)  │
└──────────┘          └──────────┘

脱敏要求:
  - 直接标识符: 删除 (姓名、身份证、电话)
  - 准标识符: K-匿名化 (年龄→年龄段, 地址→城市级)
  - 敏感属性: t-接近性 (确保分布不可区分)
```

## 九、数据治理成熟度模型

| 级别 | 能力 | 工具 | 适用团队 |
|------|------|------|---------|
| **L0: 临时** | 无版本管理, 无血缘 | 手工操作 | 个人项目 |
| **L1: 基本** | 数据版本化 (DVC) | DVC + Git | 小团队 |
| **L2: 管理** | +血缘追踪 +质量检查 | DVC + OpenLineage + Great Expectations | 中型团队 |
| **L3: 主动** | +隐私工程 +自动合规 | L2 + Presidio + Opacus | 企业 |
| **L4: 优化** | +合成数据 +联邦学习 | L3 + SDV + FATE | 大型企业 |
| **L5: 自治** | 全自动治理闭环 | AI驱动的治理Agent | 前沿 |

```
