## 1. 架构范式跃迁：从云端集中到云边端协同

> [!important] 亿级的核心认知
> 百万方案的 Cell-based（4-6 Cell + 单层控制平面）在亿级下会崩溃：50-100+ Cell 无法单层管理、2-6 万卡 GPU 逼近全球年产能、跨 Cell 流量 Tbps 级。**必须引入边缘层 + 三层控制平面**。

### 1.1 三种架构路径对比

| 方案 | 适用 | 月成本 | 实时延迟 | GPU 需求 | 复杂度 |
|------|------|--------|---------|---------|--------|
| **A · 纯云端（维持百万方案）** | < 500 万用户 | $80M+ | 100-500ms ✗ | 6万卡（产能极限）✗ | 中 |
| **B · 云+边三层** ✓ | 亿级全球用户 | $80M-200M | <50ms ✓ | 2-3万卡（可承受）✓ | 极高 |
| **C · 端侧优先** | 极致成本 | $30M-80M | <10ms ✓ | 1万卡 | 极高（端侧框架） |

**本方案选 B**：云+边三层 + 全球联邦 + 标准企业合规。

### 1.2 百万 → 亿级的 9 大质变点

| 维度 | 百万（[[14-百万用户级超级架构方案]], [[16-Agent编排层框架生态选型]]） | 亿级（本方案） | 质变本质 |
|------|--------------------------------|--------------|---------|
| 架构形态 | Cell-based（两层） | **云+边三层**（Edge→Cell→Hub） | 70-80% 请求在边缘解决 |
| Cell 数量 | 4-6 | **50-100+** | 单层控制平面崩溃，需分层 |
| 控制平面 | 单层（Global） | **三层**（Global→Regional→Cell） | 分而治之 |
| GPU 规模 | 200-600 卡 | **2万-6万卡** | 逼近全球产能，需产能策略 |
| 边缘节点 | 无 | **百万级**（CDN+设备） | 模型分发成为核心挑战 |
| 模型分发 | CDN 单层 | **分层缓存**（Hub→Cell→Edge） | 100GB 权重分发到百万节点 |
| 数据规模 | 50 TB | **5 PB** | 联邦记忆升级为联邦学习 |
| 成本量级 | $1.2M/月 | **$80M-200M/月** | FinOps 升级为 AI 驱动 |
| 组织规模 | 15-30 人 | **300-500 人** | 平台工程化为独立部门 |

### 1.3 云+边三层核心原则

```
Layer 1: Edge 边缘层（百万节点）
  · 7B/14B 小模型 · CDN 边缘 + 设备端 + 5G MEC
  · 70-80% 请求在此解决（简单问答/分类/缓存命中）
  · 模型权重从 Hub → Cell → Edge 分层缓存

Layer 2: Cell 单元层（50-100+ Cell）
  · 70B 主干模型 · 每 Cell 20-70 卡 H100
  · 20-30% 请求（多轮对话/工具调用/复杂推理）
  · 复用百万方案 Cell 架构

Layer 3: Regional Hub 枢纽层（5-8 个）
  · 235B 超大模型池 · 每 Hub 1500-2500 卡
  · 5% 请求（超复杂推理）+ 联邦学习训练
  · 模型权重分发中心
```

> [!tip] 边缘分流的本质
> 亿级用户的核心瓶颈不是「用户数」，而是「GPU 产能」。全球 H100 年产能约 200 万片，亿级方案需要 2-6 万片 = 全球年产量 1-3%。**边缘分流降低云端 GPU 需求 70%，是从「不可能」变为「可能」的关键**。

## 2. 容量基线：亿级用户的负载画像

### 2.1 用户行为假设

| 维度 | 保守值 | 激进值 | 说明 |
|------|--------|--------|------|
| 注册用户 | 100,000,000 | 100,000,000 | 输入条件 |
| DAU | 30,000,000（30%） | 50,000,000（50%） | 消费级应用典型 |
| 人均日会话 | 3 | 8 | 亿级产品以轻量场景为主 |
| 会话平均轮数 | 3 | 8 | Edge 解决大部分单轮请求 |
| 每轮 LLM 调用 | 1.2 | 2 | Edge 本地调用占比高 |
| 上下文长度 | 2K tokens | 4K tokens | Edge 场景上下文短 |
| 输出长度 | 200 tokens | 500 tokens | |

### 2.2 关键指标推导

```
日推理调用数（保守）= 30,000,000 × 3 × 3 × 1.2 = 324,000,000 次/日
日推理调用数（激进）= 50,000,000 × 8 × 8 × 2 = 6,400,000,000 次/日

Edge 分流后：
  Edge 处理（75%）= 243M - 4.8B 次/日
  Cell 处理（22%）= 71M - 1.4B 次/日
  Hub 处理（3%）= 10M - 192M 次/日

峰值 QPS（总）= 3,375 - 666,667 QPS
峰值 QPS（Cell 承担，22%）= 743 - 146,667 QPS
峰值 QPS（Hub 承担，3%）= 101 - 20,000 QPS
```

### 2.3 资源估算（与百万方案对比）

| 资源 | 百万方案 | 亿级方案 | ×100 差异 |
|------|---------|---------|----------|
| **GPU（云端）** | 200-600 卡 | **2万-6万卡**（边缘分流后） | 质变：产能约束 |
| **GPU（边缘）** | 0 | **500万-1000万设备**（消费级 GPU/NPU） | 新增 |
| **Edge 节点** | 0 | **百万级**（CDN + MEC + 设备） | 新增层 |
| **Cell 数量** | 4-6 | **50-100+** | 质变：分层管理 |
| **Regional Hub** | 0 | **5-8** | 新增层 |
| **向量数据** | 50 TB | **5 PB** | 质变：联邦学习 |
| **月成本** | $1.2M | **$80M-200M** | 质变：FinOps AI |

> [!warning] GPU 产能是硬约束
> 2026 年全球 H100 年产能约 200 万片，亿级方案需要 2-6 万片 = 全球年产量的 1-3%。**必须多厂商策略（NVIDIA + AMD + 自研 ASIC）+ 边缘分流（降低云端 GPU 需求 70%）**。

### 4.2 Edge 路由决策器

```python
class EdgeRouter:
    """边缘节点路由决策：本地处理 or 回源"""

    async def route(self, request: Request) -> Response:
        # 1. 缓存命中检查（5% 请求）
        cached = await self.semantic_cache.get(request.embedding)
        if cached and cached.similarity > 0.95:
            return cached  # 直接返回，<10ms

        # 2. 意图分类（本地小模型，10ms）
        intent = await self.classify(request.text)
        if intent.complexity == 'simple':  # 70% 请求
            return await self.local_infer(request)  # 7B 模型本地处理

        # 3. 复杂请求回源 Cell（20-30%）
        if intent.complexity == 'medium':
            return await self.forward_to_cell(request)

        # 4. 超复杂请求上溯 Hub（5%）
        return await self.forward_to_hub(request)
```

### 4.4 边缘-云端协同

```python
class EdgeCloudCollaboration:
    """边缘与云端的协同推理"""

    async def collaborative_infer(self, request: Request) -> Response:
        # 1. Edge 生成初稿（7B 模型，快速但质量一般）
        draft = await self.edge_infer(request)

        # 2. Edge 自评质量（置信度评估）
        confidence = await self.assess_confidence(draft)
        if confidence > 0.9:
            return draft  # 质量足够，直接返回

        # 3. 低置信度 → 回源 Cell 精炼（70B 模型）
        refined = await self.cell_refine(request, draft)
        return refined

        # 4. 超低置信度 → 回源 Hub（235B 模型）
        # Hub 返回后，更新 Edge 缓存（学习）
        if confidence < 0.5:
            hub_result = await self.hub_infer(request)
            await self.edge_cache.update(request, hub_result)
            return hub_result
```

> [!tip] 边缘-云端协同的本质
> 不是「Edge 或云端」，而是「Edge 先答，云端兜底」。Edge 用 7B 模型快速生成初稿并自评，高置信度直接返回（70-80%），低置信度回源精炼。这比纯云端快 10 倍，比纯 Edge 质量高 30%。

## 5. 三层控制平面

### 5.1 为什么需要三层

百万方案的单层控制平面在 50-100+ Cell 下崩溃：

| 问题 | 单层（百万） | 三层（亿级） |
|------|------------|------------|
| 50+ Cell 管理 | 单点瓶颈，延迟 > 1s | 分区管理，每 Regional 管 10-20 Cell |
| Edge 百万节点 | 无法管理 | Regional 管 Edge 注册/更新 |
| 联邦学习 | 无法协调 | Regional 协调跨 Cell 梯度聚合 |
| 故障影响 | Global 挂 = 全局策略停 | Regional 挂 = 单区域停，其他正常 |

### 5.2 三层控制平面架构

```
┌─────────────────────────────────────────────────────────────┐
│ Global 全局控制平面（1 个，跨大区）                             │
│ · 全局 IAM（CRDT 同步到所有 Hub）                              │
│ · 全局计费/配额                                                │
│ · 模型版本管理（训练任务下发到 Hub）                             │
│ · FinOps AI（跨 Hub 成本优化）                                 │
│ · 全局合规策略                                                  │
│ · 全局遗忘广播                                                  │
├─────────────────────────────────────────────────────────────┤
│ Regional 区域控制平面（5-8 个，每大区 1 个 Hub）                 │
│ · Hub 内 Cell 调度（跨 Cell 容灾）                             │
│ · 联邦学习协调（跨 Cell 梯度聚合）                              │
│ · 模型权重分发到下属 Cell                                       │
│ · 区域级可观测聚合                                              │
│ · Edge 节点管理（百万级节点的注册/健康/更新）                     │
│ · 区域级容量规划                                                │
├─────────────────────────────────────────────────────────────┤
│ Cell+Edge 本地控制（50-100+ Cell，每 Cell 自治）                │
│ · Cell 内部调度（复用百万方案 SAAR）                            │
│ · Edge 模型缓存管理                                             │
│ · 本地观测 + 上报到 Regional                                    │
│ · 本地容灾（Cell 内多 AZ）                                      │
│ · 本地配额执行                                                  │
└─────────────────────────────────────────────────────────────┘
```

### 5.3 层级决策矩阵

| 决策类型 | Global | Regional | Cell+Edge |
|---------|--------|----------|-----------|
| 用户身份 | 全局唯一 | CRDT 同步 | 本地缓存 |
| 配额策略 | 全局制定 | 区域分配 | 本地执行 |
| 模型版本 | 全局发布 | 区域灰度 | 本地部署 |
| Cell 调度 | - | 跨 Cell 容灾 | Cell 内调度 |
| Edge 管理 | - | 节点注册/更新 | 本地缓存 |
| 联邦学习 | 任务下发 | 梯度聚合 | 本地训练 |
| 成本优化 | 跨 Hub 套利 | 区域 Spot 套利 | 本地缩容 |
| 容灾 | 全局策略 | 区域切换 | 本地切换 |
| 合规 | 全局策略 | 区域合规 | 本地执行 |

> [!tip] 分而治之的核心
> Global 只管「策略」，Regional 管「协调」，Cell+Edge 管「执行」。任何一层故障，下层能独立运行——这是亿级可用的关键。

### 5.4 Regional 控制平面实现

```python
class RegionalControlPlane:
    """区域控制平面：管理 10-20 个 Cell + 百万 Edge 节点"""

    async def coordinate_cells(self):
        """跨 Cell 协调"""
        # 1. 监控 Cell 健康
        for cell in self.cells:
            if not cell.healthy:
                await self.failover_cell(cell)

        # 2. 跨 Cell 负载均衡
        overloaded = [c for c in self.cells if c.load > 0.9]
        underloaded = [c for c in self.cells if c.load < 0.5]
        if overloaded and underloaded:
            await self.rebalance(overloaded, underloaded)

    async def manage_edges(self):
        """百万级 Edge 节点管理"""
        # 1. 节点注册（新 Edge 上线）
        await self.edge_registry.poll()

        # 2. 健康检查（抽样，避免百万节点全量检查）
        sample = self.edge_registry.sample(ratio=0.01)  # 1% 采样
        for node in sample:
            if not node.healthy:
                await self.edge_registry.deregister(node)

        # 3. 模型版本检查
        outdated = await self.edge_registry.get_outdated()
        if len(outdated) > len(self.edges) * 0.3:
            await self.trigger_model_update()

    async def federated_learning(self):
        """联邦学习协调"""
        # 1. 下发训练任务到 Cell
        for cell in self.cells:
            await cell.start_training(self.current_round)

        # 2. 等待 Cell 上传梯度
        gradients = await self.collect_gradients(timeout=3600)

        # 3. 梯度聚合（FedAvg）
        aggregated = self.fed_avg(gradients)

        # 4. 下发新权重
        for cell in self.cells:
            await cell.update_weights(aggregated)
```

## 6. 联邦学习与模型迭代

### 6.1 为什么需要联邦学习

亿级用户的数据规模达 5 PB，**集中式训练不可行**：

| 方式 | 数据传输 | 训练周期 | 合规 |
|------|---------|---------|------|
| 集中式 | 5 PB 数据汇总到 Hub | 数周 | 违反数据驻留 |
| **联邦学习** | 只传梯度（GB 级） | 数天 | 数据不出 Cell ✓ |

### 6.2 联邦学习架构

```
┌─────────────────────────────────────────────────────────────┐
│              Regional Hub（联邦学习协调器）                      │
│  · 下发训练任务                                                  │
│  · 收集 Cell 梯度                                               │
│  · 梯度聚合（FedAvg / FedProx）                                 │
│  · 下发新权重                                                   │
└────────────────────────┬────────────────────────────────────┘
                         │ 梯度上传（GB 级）
          ┌──────────────┼──────────────┐
          │              │              │
     ┌────▼────┐    ┌────▼────┐    ┌────▼────┐
     │ Cell-1  │    │ Cell-2  │    │ Cell-N  │
     │ 本地数据 │    │ 本地数据 │    │ 本地数据 │
     │ 本地训练 │    │ 本地训练 │    │ 本地训练 │
     │ 数据不出│    │ 数据不出│    │ 数据不出│
     └─────────┘    └─────────┘    └─────────┘
```

### 6.3 联邦学习流程

```python
class FederatedLearning:
    """联邦学习：数据不动，模型动"""

    async def train_round(self, round_id: int):
        """一轮联邦学习训练"""

        # 1. Hub 下发当前模型权重到参与 Cell
        for cell in self.participating_cells:
            await cell.load_weights(self.current_weights)

        # 2. 各 Cell 本地训练（数据不出 Cell）
        results = await asyncio.gather(*[
            cell.local_train(
                epochs=3,
                batch_size=32,
                learning_rate=1e-5
            )
            for cell in self.participating_cells
        ], timeout=3600)

        # 3. 梯度聚合（加权平均，按数据量加权）
        total_samples = sum(r.samples for r in results)
        aggregated = {
            param: sum(
                r.gradient[param] * (r.samples / total_samples)
                for r in results
            )
            for param in results[0].gradient
        }

        # 4. 差分隐私（梯度加噪，防逆向）
        aggregated = self.dp_noise(aggregated, epsilon=1.0)

        # 5. 更新全局模型
        self.current_weights = self.optimizer.step(
            self.current_weights, aggregated
        )

        # 6. 下发新权重到所有 Cell
        for cell in self.all_cells:
            await cell.update_weights(self.current_weights)

        # 7. 评估
        eval_score = await self.evaluate()
        if eval_score > self.best_score:
            self.best_score = eval_score
            await self.save_checkpoint()
```

### 6.4 联邦学习的三个坑

> [!danger] 联邦学习的失败模式
> 1. **数据异构性**：不同 Cell 的数据分布差异大 → 用 FedProx（近端优化）替代 FedAvg，限制本地更新幅度。
> 2. **通信瓶颈**：50-100 个 Cell 上传梯度 → 梯度压缩（量化 + 稀疏化），减少 10x 带宽。
> 3. **恶意 Cell**：某 Cell 投毒梯度 → Byzantine-robust 聚合（剔除异常梯度）。

### 6.5 模型迭代节奏

| 模型类型 | 迭代频率 | 训练方式 | 分发方式 |
|---------|---------|---------|---------|
| **Edge 小模型**（7B/14B） | 每周 | 联邦学习 | Hub → Cell → Edge |
| **Cell 主干模型**（70B） | 每月 | 联邦学习 + Hub 微调 | Hub → Cell |
| **Hub 超大模型**（235B） | 每季度 | Hub 集中式训练（合规数据） | Hub 内部 |

## 8. 模型分发体系

### 8.1 分层缓存架构

```
模型权重分发（235B 模型 ~470GB）：

Regional Hub（源）
  ↓ 分发到 Cell（Cell 级缓存，70B 模型 ~140GB）
    ↓ 分发到 Edge（Edge 级缓存，7B 模型 ~14GB）
      ↓ P2P 加速（Edge 节点间互传）

分层缓存命中率：
  Hub → Cell：95%（Cell 本地缓存）
  Cell → Edge：90%（Edge 本地缓存）
  Edge → 设备：80%（设备本地缓存）
```

### 8.2 Edge 模型分发

```python
class EdgeModelDistribution:
    """百万级边缘节点的模型分发"""

    async def distribute(self, model_id: str, version: str):
        # 1. 7B 模型权重推送到 Regional Hub（14GB）
        await self.hub.store(model_id, version)

        # 2. Hub 分发到下属 Cell（Cell 级缓存）
        for cell in self.cells:
            await self.hub.push_to_cell(cell, model_id, version)

        # 3. Cell 分发到 Edge（Edge 级缓存，P2P 加速）
        # 用 P2P 协议减少 Cell 出口带宽
        await self.cell.distribute_to_edges(
            model_id, version,
            strategy='p2p',  # 节点间互传，非星型分发
            max_bandwidth='10Mbps'  # 限制单节点带宽
        )

        # 4. 灰度更新（先 1% 节点，观察 1h，再全量）
        await self.canary_rollout(model_id, version, percentage=1)
        await asyncio.sleep(3600)
        if await self.health_check(model_id):
            await self.full_rollout(model_id, version)
```

### 8.3 P2P 分发协议

```python
class P2PDistribution:
    """Edge 节点间 P2P 互传，降低 Cell 出口带宽"""

    async def distribute(self, model_hash: str, edges: List[EdgeNode]):
        # 1. Cell 先推送到 10 个种子节点
        seeds = edges[:10]
        for seed in seeds:
            await self.cell.push(seed, model_hash)

        # 2. 种子节点作为 super-seeder，向其他节点分发
        # 类似 BitTorrent 协议
        for edge in edges[10:]:
            # 每个节点从 3-5 个已有节点下载（分片）
            peers = self.select_peers(seeds, n=5)
            await edge.download(model_hash, peers, chunks=64)

        # 3. 验证完整性（哈希校验）
        for edge in edges:
            if not await edge.verify(model_hash):
                await self.retry(edge, model_hash)
```

```python
class EdgeFailover:
    """Edge 节点故障的毫秒级切换"""

    async def on_edge_failure(self, failed_edge: EdgeNode):
        # 1. 从 Edge 节点列表移除
        self.edge_pool.remove(failed_edge)

        # 2. 受影响用户自动切换到最近 Edge
        affected_users = failed_edge.active_users
        for user in affected_users:
            nearest = self.find_nearest_edge(user.location)
            if nearest:
                await self.reroute(user, nearest)
            else:
                # 无可用 Edge → 回源 Cell
                await self.reroute_to_cell(user)

        # 3. 用户感知：< 10ms（TCP 连接重连）
```

```python
class FederatedPrivacy:
    """联邦学习的隐私保护"""

    async def secure_aggregation(self, gradients: List[Gradient]):
        """安全聚合：Hub 看不到单个 Cell 的梯度"""

        # 1. 各 Cell 用公钥加密梯度
        encrypted = [g.encrypt(self.hub_pubkey) for g in gradients]

        # 2. Hub 只做密文聚合（看不到明文）
        aggregated_enc = self.homomorphic_add(encrypted)

        # 3. 解密聚合结果（只有聚合后的梯度）
        aggregated = self.decrypt(aggregated_enc)

        return aggregated

    async def differential_privacy(self, gradient: Gradient, epsilon: float):
        """差分隐私：梯度加噪，防逆向训练数据"""

        noise = self.generate_noise(
            sensitivity=1.0,
            epsilon=epsilon,
            shape=gradient.shape
        )
        return gradient + noise

    async def byzantine_robust(self, gradients: List[Gradient]):
        """Byzantine 鲁棒聚合：剔除异常梯度（防投毒）"""

        # 计算梯度的中位数（而非均值，抗异常值）
        median = self.coordinate_wise_median(gradients)

        # 剔除偏离中位数过大的梯度
        filtered = [
            g for g in gradients
            if self.distance(g, median) < self.threshold
        ]

        return self.fed_avg(filtered)
```

## 14. 深度分析

### 14.1 为什么亿级必须云+边三层

```
纯云端方案在亿级的死法：

1. GPU 产能不足
   · 6 万卡 = 全球 H100 年产量 3%
   · 采购周期 12-18 个月，无法快速扩容

2. 延迟不可接受
   · 全球用户到 Cell 的 RTT 100-500ms
   · 实时场景（语音/翻译/AR）无法满足

3. 跨 Cell 流量爆炸
   · 亿级用户跨 Cell 流量 Tbps 级
   · 跨 Region 带宽成本 $5M+/月

4. 成本失控
   · 纯云端月成本 > $200M
   · GPU 占 80%+，无优化空间

云+边三层方案：
   · 边缘分流 70%，云端 GPU 需求降 70%
   · Edge 延迟 < 50ms，满足实时场景
   · 跨 Cell 流量降 80%
   · 月成本 $80M-200M（可控）
```

### 14.4 关键决策的批判性审视

> [!abstract] 用「The Fool」批判性思维复盘
> 本方案的关键决策值得用 [[06-生产级框架选型批判性决策指南|../09-Agent框架生态/06-生产级框架选型批判性决策指南]] 的五模式再审视：
>
> - **Expose My Assumptions**：假设 70% 请求能被 Edge 解决——如果用户场景偏复杂（企业级 Agent），Edge 分流率可能只有 30%
> - **Argue the Other Side**：为什么不端侧优先？因为 Agent 需要工具调用和长程推理，端侧 7B 模型能力不足
> - **Find the Failure Modes**：最可能死在"联邦学习的数据异构性"——不同地区用户行为差异大，模型收敛困难
> - **Attack This**：云+边三层真的比纯云端好吗？在 5000 万以下，纯云端可能更简单经济
> - **Test the Evidence**：Edge 分流率 70-80% 基于消费级场景假设，企业级场景可能只有 30-40%

### 14.5 亿级方案的现实约束

> [!warning] 亿级方案不是技术问题，是组织问题
> 亿级 Agent 平台的挑战不在技术（本方案已覆盖），而在：
> - **GPU 采购**：2-6 万卡需要 12-18 个月提前锁定，与 NVIDIA/AMD 签战略合约
> - **组织规模**：300-500 人的平台工程团队，需要清晰的部门边界
> - **资金**：月成本 $80M-200M，年成本 $1B-2.4B，需要充足的融资支持
> - **合规**：全球 50+ 国家的数据合规，需要专业法务团队
> - **生态**：自研 ASIC 需要 3-5 年，需要长期投入
