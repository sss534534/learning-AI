## 1. 为什么流式架构是AI系统的生命线

AI应用从"批处理"进化到了"实时交互"。用户期望在200ms内看到第一个token，50ms内看到后续每个token。这不仅是体验问题——如果首token延迟超过2秒，转化率下降30%+。

> 流式不是"锦上添花"，是生产级AI系统的骨架。

**AI系统延迟预算分配**（以500ms总延迟为目标）:
```
用户请求
  │
  ├─ DNS + TLS 握手:      ~20ms
  ├─ API Gateway 路由:     ~5ms
  ├─ 鉴权/限流:           ~10ms
  ├─ Prompt 模板渲染:     ~5ms
  ├─ 模型推理 (TTFT):     ~300ms   ← 核心瓶颈
  │   ├─ Prefill (输入处理): ~200ms
  │   └─ First Token:       ~100ms
  ├─ 后处理 (安全/格式化): ~20ms
  └─ 网络传输至客户端:     ~40ms
                         ────────
                           ~400ms (有100ms余量)
```

```python
import asyncio
```

```python
# WebSocket 实时对话 (FastAPI)
from fastapi import WebSocket, WebSocketDisconnect

class RealtimeChatManager:
    """
    支持：
    - token流式输出
    - 用户中途打断 (barge-in)
    - 服务端主动推送 (如状态更新)
    - 音频+文本多模态
    """
    
    def __init__(self):
        self.active_connections: Dict[str, WebSocket] = {}
        self.cancel_signals: Dict[str, asyncio.Event] = {}
    
    async def handle_connection(self, websocket: WebSocket, session_id: str):
        await websocket.accept()
        self.active_connections[session_id] = websocket
        
        try:
            while True:
                # 接收消息 (文本或控制信号)
                message = await websocket.receive_json()
                
                if message["type"] == "chat":
                    # 用户发送消息，开始生成
                    await self.stream_response(session_id, message["content"])
                    
                elif message["type"] == "cancel":
                    # 用户打断当前生成
                    await self.cancel_generation(session_id)
                    
                elif message["type"] == "audio":
                    # 音频输入
                    await self.handle_audio(session_id, message["data"])
                    
        except WebSocketDisconnect:
            del self.active_connections[session_id]
    
    async def stream_response(self, session_id: str, prompt: str):
        """流式返回响应，可被打断"""
        cancel_event = asyncio.Event()
        self.cancel_signals[session_id] = cancel_event
        
        async for chunk in model.stream_generate(prompt):
            if cancel_event.is_set():
                # 用户打断了
                await self.active_connections[session_id].send_json({
                    "type": "cancelled",
                    "partial_text": accumulated_text
                })
                break
            
            await self.active_connections[session_id].send_json({
                "type": "token",
                "content": chunk.token,
                "index": chunk.index
            })
        
        del self.cancel_signals[session_id]
```

## 3. 推理引擎的流式架构

### 3.1 Prefill-Decode 分离架构

```
传统架构 (Monolithic):
┌──────────────────────────────────┐
│  GPU 0                            │
│  ┌──────────┐  ┌───────────────┐ │
│  │ Prefill  │  │    Decode     │ │  ← 资源争抢
│  │ (计算密集)│  │ (内存密集)    │ │
│  └──────────┘  └───────────────┘ │
└──────────────────────────────────┘

分离架构 (Disaggregated):
┌──────────────────┐    KV Cache     ┌──────────────────────┐
│ Prefill Pool     │  ─────────────→  │  Decode Pool         │
│ (高算力GPU)       │    (RDMA/NVLink) │  (大显存GPU)          │
│                  │                  │                      │
│ GPU 0 (H100)     │                  │ GPU 2 (A100-80G)     │
│ GPU 1 (H100)     │                  │ GPU 3 (A100-80G)     │
└──────────────────┘                  └──────────────────────┘
     ↑                                        ↓
  输入prompt                            输出token流

优势:
  - Prefill不阻塞Decode (解耦资源)
  - 独立扩缩: Prefill按QPS扩，Decode按并发扩
  - 异构GPU: Prefill用高算力，Decode用大显存
  - KV Cache传输一次，多步Decode复用
```

### 3.2 Continuous Batching — 流式吞吐的核心

```python
# Continuous Batching 调度器核心逻辑
class ContinuousBatchingScheduler:
    """
    与Static Batching对比:
    Static: [req1, req2, req3] 必须等最慢的完成才能整批换新
    Continuous: 每步都可加/减请求
    
    吞吐提升: 5-10x (长尾请求不再阻塞整个batch)
    """
    
    def __init__(self, max_batch_size, max_num_seqs, block_size=16):
        self.running: List[Sequence] = []    # 正在生成的请求
        self.waiting: List[Sequence] = []    # 等待处理的请求
        self.block_manager = BlockManager(block_size)
    
    def step(self) -> GenerationStep:
        """
        每步推理迭代:
        1. 检查是否有完成的请求 → 移除
        2. 检查是否有空闲位置 → 加入新请求
        3. 运行一次forward
        4. 采样并更新状态
        """
        
        # 1. 移除完成的请求
        newly_completed = []
        for seq in self.running:
            if seq.status == SequenceStatus.FINISHED:
                newly_completed.append(seq)
            elif seq.status == SequenceStatus.WAITING:
                newly_completed.append(seq)  # 被用户取消
        
        for seq in newly_completed:
            self.running.remove(seq)
            self.block_manager.free(seq.blocks)
            self._return_to_client(seq)
        
        # 2. 尝试加入新请求
        while (len(self.running) < self.max_num_seqs and 
               self.waiting and 
               self.block_manager.can_allocate()):
            
            seq = self.waiting.pop(0)
            
            # Prefill: 处理输入prompt
            prefill_blocks = self.block_manager.allocate(
                seq.prompt_len // self.block_size + 1
            )
            seq.blocks = prefill_blocks
            
            # 检查prefix cache
            if shared_prefix := self._find_prefix_cache(seq.prompt_hash):
                seq.blocks[:len(shared_prefix)] = shared_prefix
            
            self.running.append(seq)
        
        # 3. 运行forward
        model_inputs = self._prepare_inputs(self.running)
        logits = self.model.forward(model_inputs)
        
        # 4. 采样
        for i, seq in enumerate(self.running):
            next_token = self.sampler.sample(logits[i], seq.sampling_params)
            seq.append_token(next_token)
            
            if next_token == seq.stop_token or seq.len >= seq.max_len:
                seq.status = SequenceStatus.FINISHED
        
        return GenerationStep(
            new_tokens=[seq.last_token for seq in self.running],
            completed=[seq for seq in newly_completed]
        )
```

## 4. 延迟SLO设计与监控

### 4.1 关键延迟指标

| 指标 | 全称 | 定义 | 目标 | 监控方式 |
|------|------|------|------|----------|
| **TTFT** | Time to First Token | 请求发送→第一个token到达 | p50<200ms, p95<500ms | histogram |
| **TPOT** | Time per Output Token | 相邻token间延迟 | p50<30ms, p95<80ms | histogram |
| **TBT** | Time Between Tokens | 客户端感知的token间隔（含网络） | p50<50ms | client-side |
| **E2E Latency** | End-to-End | 完整请求-响应时间 | p95<5s | histogram |
| **TPT** | Tokens Per Second | 每秒生成token数（吞吐） | >50 tps/req | gauge |
| **Queue Time** | 排队时间 | 请求排队等待GPU的时间 | p95<100ms | histogram |

```python
# 延迟监控系统设计
class LatencyMonitor:
    """
    多维度延迟监控，实时告警
    """
    
    def __init__(self):
        self.metrics = PrometheusMetrics()
    
    def record_request(self, request_id: str, timestamps: RequestTimestamps):
        """记录完整的请求时间线"""
        
        # 各阶段延迟
        phases = {
            "queue_time": timestamps.schedule_start - timestamps.received,
            "prefill_time": timestamps.prefill_end - timestamps.prefill_start,
            "first_token_time": timestamps.first_token - timestamps.received,
            "decode_step_time": timestamps.decode_steps,  # List[float]
            "total_time": timestamps.finished - timestamps.received,
            "tokens_per_second": (
                timestamps.total_tokens / 
                (timestamps.finished - timestamps.first_token).total_seconds()
            )
        }
        
        # 记录Prometheus指标
        for name, value in phases.items():
            if isinstance(value, list):
                for v in value:
                    self.metrics.histogram(f"llm_{name}_ms", v * 1000)
            else:
                self.metrics.histogram(f"llm_{name}_ms", value * 1000)
        
        # 记录按模型/版本的指标
        labels = {
            "model": timestamps.model_name,
            "version": timestamps.model_version,
            "request_type": timestamps.request_type
        }
        self.metrics.histogram(
            "llm_ttft_ms", 
            phases["first_token_time"] * 1000, 
            labels=labels
        )
    
    def check_slo(self) -> List[SLOViolation]:
        """检查SLO是否违规"""
        violations = []
        
        # 滑动窗口检查
        for window, slo_config in self.slo_windows.items():
            metrics = self.metrics.query_range(window)
            
            for metric, threshold in slo_config.items():
                if metrics[metric].p95 > threshold:
                    violations.append(SLOViolation(
                        metric=metric,
                        window=window,
                        actual=metrics[metric].p95,
                        threshold=threshold,
                        severity="CRITICAL" if metrics[metric].p95 > threshold * 2 else "WARNING"
                    ))
        
        return violations
```

### 5.1 背压机制

```python
# 多级背压系统
class BackpressureController:
    """
    当推理集群过载时，逐级施加背压:
    
    Level 1: 增加排队 → 请求进入等待队列
    Level 2: 拒绝低优先级 → 返回429 (非vip用户)
    Level 3: 降级服务   → 切换到更小/更快模型
    Level 4: 限流       → 全局限流，返回503
    """
    
    def __init__(self):
        self.pressure_level = 0  # 0-4
        self.model_pool = {
            "primary": "gpt-4o",
            "fallback_fast": "gpt-4o-mini",  # 降级模型
            "fallback_local": "llama-3-70b"   # 本地降级
        }
    
    def check_and_apply_backpressure(self, queue_depth: int, gpu_util: float) -> PressureLevel:
        """根据系统负载决定背压等级"""
        
        if queue_depth > 1000 or gpu_util > 0.95:
            self.pressure_level = 4
        elif queue_depth > 500 or gpu_util > 0.85:
            self.pressure_level = 3
        elif queue_depth > 200 or gpu_util > 0.75:
            self.pressure_level = 2
        elif queue_depth > 50:
            self.pressure_level = 1
        else:
            self.pressure_level = 0
        
        return self.pressure_level
    
    def handle_request(self, request: Request) -> Response:
        """根据背压等级处理请求"""
        level = self.pressure_level
        
        if level == 0:
            # 正常处理
            return self.normal_serve(request)
        
        elif level == 1:
            # 增加排队，添加Retry-After头
            response = self.normal_serve(request)
            response.headers["X-Queue-Depth"] = str(self.queue_depth)
            return response
        
        elif level == 2:
            # 拒绝低优先级用户
            if request.user_tier != "enterprise":
                return Response(status=429, body={"retry_after": 5})
            return self.normal_serve(request)
        
        elif level == 3:
            # 降级服务
            if request.allow_fallback:
                return self.fallback_serve(request, model="gpt-4o-mini")
            return Response(status=429, body={"retry_after": 10})
        
        elif level == 4:
            # 全局限流
            return Response(status=503, body={
                "error": "Service overloaded",
                "retry_after": 30
            })
```

### 5.2 削峰填谷策略

```python
# Token预算 + 优先级队列 削峰
class TokenRateLimiter:
    """
    基于token的速率限制，比RPM更精确
    
    实现:
    - 每分钟给每个用户分配token预算
    - 输入 + 输出token都计入
    - 超过预算 → 排队或降级
    - 实现类似TCP拥塞控制的AIMD算法
    """
    
    def __init__(self, tpm_limit: int = 1_000_000):
        self.tpm_limit = tpm_limit
        self.window = 60  # 60秒滑动窗口
        self.usage: Dict[str, Deque[Tuple[float, int]]] = {}
    
    def check_and_consume(self, user_id: str, tokens_estimate: int) -> RateLimitResult:
        """检查并消耗token预算"""
        now = time.time()
        
        # 清理过期记录
        if user_id in self.usage:
            while self.usage[user_id] and self.usage[user_id][0][0] < now - self.window:
                self.usage[user_id].popleft()
        
        # 计算当前窗口使用量
        current_usage = sum(tokens for ts, tokens in self.usage.get(user_id, []))
        
        if current_usage + tokens_estimate > self.tpm_limit:
            # 超限，返回等待时间
            oldest_ts = self.usage[user_id][0][0]
            wait_until = oldest_ts + self.window
            return RateLimitResult(
                allowed=False,
                retry_after=max(0, wait_until - now),
                current_usage=current_usage
            )
        
        # 允许，记录使用
        if user_id not in self.usage:
            self.usage[user_id] = deque()
        self.usage[user_id].append((now, tokens_estimate))
        
        return RateLimitResult(allowed=True)
```

## 6. 流式RAG架构

### 6.1 流式检索+生成

```python
# 流式RAG：检索和生成并行
class StreamingRAG:
    """
    传统RAG: 检索 → 等所有结果 → 生成 (串行)
    流式RAG: 检索 → 逐条到达 → 逐条注入生成 (并行)
    
    优势: TTFT降低50%+
    """
    
    async def stream_rag_response(self, query: str):
        # 1. 发起异步检索（不等待全部结果）
        retrieval_stream = self.async_retrieve(query, top_k=10)
        
        # 2. 第一批结果到达就开始生成
        first_chunk = await retrieval_stream.get_first(k=3)
        
        # 构建初始上下文
        current_context = self.format_context(first_chunk)
        
        # 3. 边检索边生成
        generation_task = asyncio.create_task(
            self.stream_generate(query, current_context)
        )
        retrieval_task = asyncio.create_task(
            self.collect_remaining(retrieval_stream)
        )
        
        # 4. 当新文档到达时，动态更新上下文
        async for token in generation_task:
            if retrieval_task.done() or self.context_updated:
                # 有新文档到达，更新生成上下文
                # 注意：这需要模型支持动态KV Cache更新
                # 实际中通常在下一个generation turn时更新
                pass
            yield token

    async def async_retrieve(self, query: str, top_k: int):
        """异步检索，按相似度降序返回"""
        # 向量检索
        vector_results = await self.vector_search(query, top_k)
        for result in vector_results:
            yield result
            await asyncio.sleep(0)  # yield给调用方
        
        # BM25检索 (补充)
        bm25_results = await self.bm25_search(query, top_k)
        for result in bm25_results:
            yield result
```

```python
class StreamingAgent:

            elif "Final Answer:" in thought:
                # 最终答案，流式输出
                async for token in self.llm.stream(f"Final Answer: "):
                    yield AgentStreamEvent(type="final_token", content=token)
                break
```

## 7. 实时语音AI — 终极流式挑战

### 7.1 延迟预算 — 人类的耐心极限

```
语音对话的延迟预算 (总目标 <500ms，人类对话延迟 ~200ms):

┌──────────────────────────────────────────────────────┐
│ 麦克风采集:          20ms                            │
│ VAD (语音活动检测):  20ms                            │
│ ASR (语音识别):      100ms  ← 关键瓶颈               │
│ LLM推理 (TTFT):      150ms                           │
│ TTS (语音合成):      100ms  ← 关键瓶颈               │
│ 音频播放:            20ms                            │
│ 网络+序列化:         50ms                            │
├──────────────────────────────────────────────────────┤
│ 总计:                460ms (可接受)                   │
└──────────────────────────────────────────────────────┘

优化策略:
  - 流式ASR: 边说边识别，减少首字延迟
  - 流式TTS: 边生成边合成，token→audio chunk
  - 打断检测: 用户说话时立即停止当前生成
  - 预测缓存: 对常见回复预计算
```

### 7.2 全双工语音架构

```python
# 全双工语音对话架构
class FullDuplexVoiceAgent:
    """
    核心能力:
    1. 用户可在任何时候说话打断AI (barge-in)
    2. AI可在生成过程中被中断
    3. 支持停顿检测 vs 打断检测的平衡
    """
    
    def __init__(self):
        self.asr_pipeline = StreamingASR()    # 流式语音识别
        self.llm = StreamingLLM()             # 流式LLM
        self.tts = StreamingTTS()             # 流式语音合成
        self.vad = VoiceActivityDetector()    # 语音活动检测
        
        self.is_speaking = False              # AI是否在说话
        self.interruption_event = asyncio.Event()
    
    async def run_conversation_loop(self):
        """主对话循环"""
        
        while True:
            # 1. 等待用户开始说话
            audio_chunk = await self.mic.read()
            
            if self.vad.is_speech(audio_chunk):
                if self.is_speaking:
                    # 用户在AI说话时打断!
                    await self.handle_interruption()
                
                # 2. 采集完整语音
                user_audio = await self.collect_utterance()
                
                # 3. 流式ASR
                user_text = await self.asr_pipeline.transcribe_streaming(user_audio)
                
                # 4. LLM推理
                self.is_speaking = True
                self.interruption_event.clear()
                
                async for text_chunk in self.llm.stream(user_text):
                    # 检查是否被中断
                    if self.interruption_event.is_set():
                        break
                    
                    # 5. 流式TTS
                    audio_chunk = await self.tts.synthesize_streaming(text_chunk)
                    await self.speaker.play(audio_chunk)
                
                self.is_speaking = False
    
    async def handle_interruption(self):
        """处理用户打断"""
        # 1. 停止当前TTS播放
        await self.speaker.stop()
        
        # 2. 取消当前LLM生成
        self.interruption_event.set()
        
        # 3. 清理状态
        self.llm.cancel_current()
        self.is_speaking = False
        
        # 4. 提示用户可以说话
        await self.indicator.show_listening()
```

### 9.2 容量规划公式

```python
# 推理容量规划计算器
def capacity_planner(
    target_qps: int,           # 目标QPS
    avg_prompt_tokens: int,    # 平均输入token数
    avg_output_tokens: int,    # 平均输出token数
    gpu_tps: int,              # 单GPU的token/秒
    gpu_count_per_node: int,   # 单节点GPU数
    target_latency_p95: float, # 目标P95延迟(秒)
    buffer_factor: float = 1.3 # 余量系数
) -> CapacityPlan:
    """
    计算需要的GPU/节点数量
    """
    
    # 每个请求的总token
    tokens_per_request = avg_prompt_tokens + avg_output_tokens
    
    # 每秒总token需求
    total_tps_needed = target_qps * tokens_per_request * buffer_factor
    
    # 需要的GPU数
    gpus_needed = total_tps_needed / gpu_tps
    
    # 考虑延迟目标：Max并发 = target_latency * gpu_tps / tokens_per_request
    max_concurrent_per_gpu = target_latency_p95 * gpu_tps / tokens_per_request
    gpus_for_latency = target_qps * target_latency_p95 / max_concurrent_per_gpu
    
    # 取两者的最大值
    total_gpus = max(gpus_needed, gpus_for_latency)
    nodes_needed = ceil(total_gpus / gpu_count_per_node)
    
    return CapacityPlan(
        total_gpus=ceil(total_gpus),
        nodes=ceil(nodes_needed),
        estimated_tps_per_gpu=gpu_tps,
        max_concurrent=ceil(max_concurrent_per_gpu * total_gpus),
        cost_estimate=total_gpus * GPU_HOURLY_COST
    )
```
