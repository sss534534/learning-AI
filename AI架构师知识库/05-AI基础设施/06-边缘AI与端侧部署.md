## 1. 为什么边缘AI正在爆发

2025-2026年，三个趋势交汇推动了边缘AI的质变：

1. **硬件成熟**: Apple M4/A18 Pro的NPU达38 TOPS，骁龙8 Elite达45 TOPS，端侧可跑7B+模型
2. **模型压缩**: 量化到INT4/INT2的7B模型仅需3-4GB，适配移动端
3. **隐私驱动**: Apple Intelligence、Android AICore都在推动本地推理优先

> 边缘AI不是"阉割版云端AI"，而是全新的架构范式。

**边缘vs云端决策矩阵**:
```
        延迟    隐私    成本    算力    模型灵活度
云端     中      低      高      极高       高
边缘     极低    极高    低      中低       低
端云协同  低     中高    中      高         高
```

### 2.3 GGUF量化格式深度

```
GGUF量化级别对照表:

格式      类型    模型大小(7B)   质量损失   推理速度   适用场景
─────────────────────────────────────────────────────────
F16       原始     ~14 GB        无        基准       开发调试
F32       原始     ~28 GB        无        最慢       训练
Q8_0      INT8    ~7.7 GB       ~0.1%     1.5x      高精度推理
Q6_K      6-bit   ~6.3 GB       ~0.3%     1.8x      质量优先
Q5_K_M    5-bit   ~5.5 GB       ~0.5%     2.0x      平衡选择
Q4_K_M    4-bit   ~4.9 GB       ~1.0%     2.5x      ★ 移动端推荐
Q4_0      INT4    ~4.3 GB       ~1.5%     2.8x      速度优先
Q3_K_M    3-bit   ~4.0 GB       ~3.0%     3.0x      极限压缩
Q2_K      2-bit   ~3.3 GB       ~8.0%     3.5x      嵌入式/MCU
IQ4_XS    HQQ     ~4.5 GB       ~0.8%     2.3x      质量-速度最优
IQ3_XXS   HQQ     ~3.5 GB       ~1.5%     3.0x      手机8GB RAM

K-quant 命名规则:
  Q{bits}_K_{size}: K=K-quant混合精度, size=S(小)/M(中)/L(大)
  I-quant: importance-aware量化, 对重要权重保留更高精度
```

### 3.2 AWQ vs GPTQ — 两大PTQ王者

```python
# AWQ (Activation-aware Weight Quantization)
# 核心: 基于激活值分布保护重要通道
from awq import AutoAWQForCausalLM

# 1. 加载模型
model = AutoAWQForCausalLM.from_pretrained(
    "meta-llama/Llama-3-8B-Instruct"
)

# 2. 量化 (自动校准)
model.quantize(
    tokenizer=tokenizer,
    quant_config={
        "zero_point": True,       # 使用zero-point
        "q_group_size": 128,      # 分组大小
        "w_bit": 4,              # 4-bit
        "version": "GEMM"        # GEMM内核 (更快)
    },
    calib_data="pileval"         # 校准数据集
)

# 3. 保存
model.save_quantized("llama-3-8b-awq")

# GPTQ (更成熟的生态，但AWQ通常更快)
from auto_gptq import AutoGPTQForCausalLM

model = AutoGPTQForCausalLM.from_pretrained(
    "meta-llama/Llama-3-8B-Instruct",
    quantize_config=BaseQuantizeConfig(
        bits=4,
        group_size=128,
        desc_act=False  # 是否使用descending activation
    )
)
```

```swift
import MetalPerformanceShaders

class MetalInference {
    let device: MTLDevice
    let commandQueue: MTLCommandQueue
    
    func runMatMul(A: MPSMatrix, B: MPSMatrix, C: MPSMatrix) {
        let commandBuffer = commandQueue.makeCommandBuffer()!
        
        // 使用MPS矩阵乘法
        let matMul = MPSMatrixMultiplication(
            device: device,
            transposeLeft: false,
            transposeRight: false,
            resultRows: A.rows,
            resultColumns: B.columns,
            interiorColumns: A.columns,
            alpha: 1.0,
            beta: 0.0
        )
        
        matMul.encode(commandBuffer: commandBuffer, leftMatrix: A, rightMatrix: B, resultMatrix: C)
        commandBuffer.commit()
        commandBuffer.waitUntilCompleted()
    }
}
```

## 5. 端云协同架构

### 5.1 三层架构模式

```
端云协同三层模型:

Layer 1: 端侧 (On-Device)
  ├── 场景: 实时响应、离线可用、隐私敏感
  ├── 模型: 3B-7B量化模型 (GGUF Q4_K_M)
  ├── 延迟: <50ms
  ├── 任务: 文本补全、简单问答、意图分类、敏感数据摘要
  └── 触发: 所有请求先走端侧
  
Layer 2: 边缘节点 (Edge Node)
  ├── 场景: 近距离低延迟 + 更强算力
  ├── 模型: 13B-20B模型
  ├── 延迟: <100ms
  ├── 任务: 复杂推理、知识检索、翻译
  └── 触发: 端侧能力不足时fallback
  
Layer 3: 云端 (Cloud)
  ├── 场景: 最强能力、最新模型
  ├── 模型: 70B+ / GPT-4级别
  ├── 延迟: <500ms
  ├── 任务: 深度推理、多模态理解、代码生成
  └── 触发: 检测到复杂任务时主动升级
```

### 5.2 智能路由实现

```python
# 端云协同智能路由器
class EdgeCloudRouter:
    """
    根据任务复杂度、网络状态、用户偏好动态选择推理位置
    """
    
    def __init__(self):
        self.models = {
            "on_device": {
                "model": "Qwen2-7B-Q4_K_M",
                "capability_score": 0.5,   # 相对能力评分
                "latency_ms": 30,
                "cost_per_token": 0,
            },
            "edge": {
                "model": "Qwen2-20B-Q4_K_M",
                "capability_score": 0.7,
                "latency_ms": 80,
                "cost_per_token": 0.0001,
            },
            "cloud": {
                "model": "gpt-4o",
                "capability_score": 1.0,
                "latency_ms": 400,
                "cost_per_token": 0.00001,
            }
        }
    
    def route(self, request: AIRequest) -> RoutingDecision:
        """智能路由决策"""
        
        # 1. 隐私优先：敏感数据强制端侧
        if self.contains_pii(request.content):
            return RoutingDecision(target="on_device", reason="隐私保护")
        
        # 2. 离线优先
        if request.network_quality == "offline":
            return RoutingDecision(target="on_device", reason="离线模式")
        
        # 3. 复杂度评分（基于prompt模板/长度/历史等）
        complexity = self.estimate_complexity(request)
        
        if complexity < 0.3:
            target = "on_device"
        elif complexity < 0.6:
            target = "edge"
        else:
            target = "cloud"
        
        # 4. 延迟预算检查
        model = self.models[target]
        if request.max_latency_ms and model["latency_ms"] > request.max_latency_ms:
            # 降级到更快的层级
            if target == "cloud":
                target = "edge"
            elif target == "edge":
                target = "on_device"
        
        return RoutingDecision(
            target=target,
            model=model["model"],
            reason=f"复杂度{complexity:.2f} → {target}"
        )
    
    def estimate_complexity(self, request: AIRequest) -> float:
        """快速估计任务复杂度 (0-1)"""
        factors = {
            "prompt_length": min(request.prompt_len / 4000, 1.0) * 0.3,
            "has_code": 0.3 if any(kw in request.content.lower() 
                for kw in ["code", "function", "class", "debug", "error"]) else 0.0,
            "has_reasoning": 0.2 if any(kw in request.content.lower()
                for kw in ["analyze", "compare", "evaluate", "为什么", "分析"]) else 0.0,
            "multi_turn": 0.1 * min(request.conversation_turns / 5, 1.0),
            "tool_use": 0.2 if request.requires_tools else 0.0,
        }
        return min(sum(factors.values()), 1.0)
```

## 8. 生产部署检查清单

```
边缘AI部署检查清单:

□ 模型选择
  □ 目标设备RAM/Flash容量是否满足 (~模型大小 × 1.5)
  □ 推理速度是否满足延迟目标 (benchmark确认)
  □ 精度是否可接受 (量化损失验证)

□ 模型优化
  □ 选择了合适的量化格式 (Q4_K_M / AWQ / GPTQ)
  □ 使用了设备原生推理引擎 (CoreML / QNN / OpenVINO)
  □ 启用了GPU/NPU加速

□ 安全与隐私
  □ 模型文件加密存储 (防止逆向)
  □ 输入/输出不离开设备 (或脱敏后上传)
  □ 使用Secure Enclave保护密钥

□ OTA更新
  □ 模型可远程更新 (增量更新, 减小下载)
  □ 版本管理与回滚机制
  □ A/B测试框架 (新模型灰度)

□ 监控
  □ 端侧性能指标上报 (延迟/内存/电量)
  □ 模型质量指标 (用户反馈/准确率)
```
