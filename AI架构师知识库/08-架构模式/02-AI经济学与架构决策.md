## 一、AI系统TCO模型

### 1.1 TCO全景

```
AI系统TCO = 基础设施 + 软件 + 人力 + 数据 + 机会成本

┌─────────────────────────────────────────┐
│              基础设施 (35-50%)            │
│  GPU云/自建 | 网络 | 存储 | 冷却        │
├─────────────────────────────────────────┤
│              软件 & 服务 (15-25%)        │
│  模型API | 商业许可 | 工具链 | 监控     │
├─────────────────────────────────────────┤
│              人力 (20-30%)               │
│  ML工程师 | 平台工程师 | SRE | PM       │
├─────────────────────────────────────────┤
│              数据 (5-15%)                │
│  数据采集 | 标注 | 存储 | 治理          │
├─────────────────────────────────────────┤
│              机会成本 (5-10%)             │
│  自研vs购买的时间差 | 延迟上市           │
└─────────────────────────────────────────┘
```

### 1.2 GPU成本建模

| 方案 | 单位成本 | TCO/年 (8×H100) | 适用 |
|------|---------|-----------------|------|
| **云GPU按需** | $2.5-3.5/GPU/h | ~$175K | 实验/PoC |
| **云GPU预留(1年)** | $1.5-2.0/GPU/h | ~$110K | 稳定训练 |
| **云GPU预留(3年)** | $1.0-1.5/GPU/h | ~$80K | 长期推理 |
| **自建DGX H100** | $300K/节点 | ~$85K (含运维) | 大规模训练 |
| **Serverless GPU** | $0.0004/sec | 按量 | 突发推理 |

**盈亏平衡分析**：
```
自建 vs 云 盈亏平衡:

自建: 首年 $300K + 运维 $50K/年
云预留: $80K/年

自建第1年总成本 > 云预留:
  Year 1: $350K vs $80K → 云更便宜

自建第4年总成本 < 云预留:
  Year 4: $500K vs $320K → 自建更便宜
  
结论: 自建在3.5年回本,GPU利用率 > 60%时划算
```

### 1.3 API vs 自部署成本

| 场景 | GPT-4o API | 自部署 Llama-70B (4×H100) |
|------|-----------|--------------------------|
| **100 req/day** | $5-15/月 | $8,000/月 (GPU) → API完胜 |
| **10K req/day** | $500-1,500/月 | $8,000/月 → API仍便宜 |
| **100K req/day** | $5,000-15,000/月 | $8,000/月 → 临界点 |
| **1M req/day** | $50,000-150,000/月 | $16,000/月 (2节点) → 自部署胜 |

**隐藏成本**：
- API：延迟不可控、数据隐私风险、供应商锁定
- 自部署：运维人力 (1-2 FTE)、冷启动时间、模型更新成本

## 二、Build vs Buy 决策框架

### 2.1 决策矩阵

| 组件 | Build (自研) | Buy (购买) | 推荐 |
|------|------------|-----------|------|
| **LLM推理服务** | vLLM自建 | OpenAI/Anthropic API | 小规模→Buy,大规模→Build |
| **向量数据库** | FAISS/PGVector | Pinecone/Weaviate | 原型→Buy,生产→Build |
| **Agent框架** | 自研Agent | LangChain/CrewAI | 核心IP→Build,非核心→Buy |
| **Prompt管理** | Git托管 | LangSmith/Humanloop | 小团队→Build,企业→Buy |
| **评估平台** | 自研脚本 | Braintrust/DeepEval | 初期→Build,规模化→Buy |
| **监控可观测** | Grafana+Prometheus | LangSmith/Datadog LLM | 视团队能力 |
| **安全护栏** | 规则+Nemo Guardrails | Lakera/Aporia | 推荐Buy(安全更新快) |

### 2.2 决策树

```
这个组件是核心差异化吗?
├── 是 → Build (自研)
│   └── 但考虑: 是否有自研能力? ROI?
│
├── 否 → 规模多大?
    ├── 小 (<100 req/min)  → Buy (API/SaaS)
    ├── 中 (100-1K req/min) → Buy (但评估自研)
    └── 大 (>1K req/min)    → Build (考虑总成本)
    
特殊考量:
  - 数据隐私/合规 → Build
  - 极致延迟要求 → Build  
  - 需要定制化 → Build
  - 快速上市 → Buy
```

### 2.3 开源 vs 商业模型

| 维度 | 开源模型 (Llama/Qwen/DeepSeek) | 商业API (GPT-4o/Claude) |
|------|-------------------------------|------------------------|
| **成本** | 低(仅GPU) / 高(一次性投入) | 高(持续) |
| **质量** | 快速追赶,差距缩小 | 领先但边际优势在减 |
| **可控性** | 完全可控(微调/量化) | 有限(参数不可调) |
| **隐私** | 本地部署,数据不出域 | 数据发送到第三方 |
| **稳定性** | 自维护 | 99.9% SLA |
| **更新** | 手动升级 | 自动获得最新模型 |
| **合规** | 完全合规(自主) | 需审核供应商 |

**2026年趋势**：开源模型质量已达商业模型90-95%, 成本优势成为决定性因素。

## 三、API经济与定价策略

### 3.1 定价模型对比

| 模型 | 定价策略 | 优势 | 劣势 |
|------|---------|------|------|
| **OpenAI** | 按Token(输入/输出差异) | 精细计费,低成本探索 | 输出成本高 |
| **Anthropic** | 按Token + 缓存折扣 | 重复提示省钱 | 仅文本 |
| **Google Gemini** | 按Token + 免费层 | 大免费额度 | 质量略逊 |
| **DeepSeek** | 极低Token价 | 成本优势巨大 | 功能较少 |
| **Together AI** | 按GPU时+按Token两种 | 灵活 | 小众 |

### 3.2 内部定价(FinOps)

```python
# 内部chargeback模型
class ChargebackModel:
    """内部计费: 成本 + 运维溢价"""
    
    # 成本基数 (每1K tokens)
    base_costs = {
        "gpt-4o": {"input": 0.0025, "output": 0.01},
        "self-hosted-llama-70b": {
            "input": 0.00008,   # 纯GPU成本
            "output": 0.00032,
        }
    }
    
    # 定价策略
    def price(self, model: str, tokens: dict, strategy: str) -> float:
        base = self.base_costs[model]
        cost = (tokens["input"] * base["input"] + 
                tokens["output"] * base["output"]) / 1000
        
        if strategy == "cost_plus":
            # 成本 + 30% 运维费用
            return cost * 1.3
        elif strategy == "subsidy":
            # 补贴内部使用,仅收成本
            return cost
        elif strategy == "market":
            # 接近市场价格 (但低20%)
            market_price = cost * 2.0
            return market_price * 0.8
        
        return cost
    
    # 阶梯折扣
    def volume_discount(self, monthly_usage: float) -> float:
        if monthly_usage > 10000:
            return 0.7  # 30% off
        elif monthly_usage > 5000:
            return 0.85
        elif monthly_usage > 1000:
            return 0.95
        return 1.0
```

## 四、ROI分析与投资决策

### 4.1 AI项目ROI模型

```
ROI = (收益 - 成本) / 成本 × 100%

AI项目收益类型:
  1. 效率提升 (人力节省): 可量化
     例: 客服机器人 → 减少10个客服 → $500K/年
  
  2. 收入增长 (新功能/产品): 可估算
     例: AI推荐 → 转化率+15% → $2M/年
  
  3. 质量提升 (错误减少): 难量化
     例: 代码审查 → Bug减少30% → ?
  
  4. 战略价值 (能力构建): 不可量化
     例: AI能力储备 → 未来竞争力
```

### 4.2 ROI计算器

```python
def ai_project_roi(
    # 成本
    gpu_monthly: float,        # GPU月租
    api_monthly: float,        # API月费
    engineering_fte: int,      # 工程师人年
    fte_salary: float = 150000, # 年薪
    initial_setup: float = 0,  # 一次性投入
    
    # 收益
    headcount_saved: int = 0,  # 节省人头
    revenue_increase: float = 0, # 增收
    cost_saved_other: float = 0, # 其他节省
    
    # 参数
    years: int = 3
) -> dict:
    annual_cost = (
        gpu_monthly * 12 +
        api_monthly * 12 +
        engineering_fte * fte_salary
    )
    annual_benefit = (
        headcount_saved * fte_salary +
        revenue_increase +
        cost_saved_other
    )
    
    total_cost = initial_setup + annual_cost * years
    total_benefit = annual_benefit * years
    
    return {
        "annual_cost": annual_cost,
        "annual_benefit": annual_benefit,
        "total_cost_3yr": total_cost,
        "total_benefit_3yr": total_benefit,
        "roi_3yr": (total_benefit - total_cost) / total_cost * 100,
        "payback_months": initial_setup / (annual_benefit - annual_cost) * 12 
            if annual_benefit > annual_cost else float('inf'),
        "break_even": "可行" if annual_benefit > annual_cost else "不可行"
    }

# 示例: RAG知识库项目
result = ai_project_roi(
    gpu_monthly=5000,
    api_monthly=2000,
    engineering_fte=2,
    initial_setup=100000,
    headcount_saved=4,      # RAG替代人工查找
    revenue_increase=200000  # 新产品收入
)
# {
#   "annual_cost": 384000,
#   "annual_benefit": 800000,
#   "roi_3yr": 108.3%,
#   "payback_months": 2.9,
#   "break_even": "可行"
# }
```

## 五、多云与供应商策略

### 5.1 多云成本优化

```
单云风险:
  - 供应商锁定 (涨价, 停服)
  - 单点故障 (区域宕机)
  - 容量不足 (GPU供不应求)

多云策略:
  Tier 1: 主力云 (60% 工作负载)
  Tier 2: 备用云 (30%)
  Tier 3: 突发/边缘 (10%)

成本套利:
  监控各云GPU价格 → 自动路由到最便宜 → 节省20-40%
```

### 5.2 供应商风险管理

| 风险 | 缓解措施 |
|------|---------|
| **API涨价** | 核心场景自部署开源模型 |
| **API停服** | 多供应商 + 模型抽象层 |
| **模型质量下降** | 持续评估 + 自动回退 |
| **合规变更** | 私有化部署能力储备 |
| **GPU供应中断** | 跨云GPU池 + 预留实例 |

## 六、成本感知架构设计

### 6.1 成本感知模式

```
模式1: 智能降级
  if cost_per_request > budget:
    switch to cheaper model  # GPT-4o → GPT-4o-mini
  
模式2: 缓存优先
  check semantic cache → hit? → zero cost
  miss → call model → cache result

模式3: 批量优惠
  非实时请求 → 攒批 → 批量推理 → GPU利用率↑, 成本↓

模式4: 混合推理
  简单问题 → 小模型 (cheap)
  复杂问题 → 大模型 (expensive)
  → 平均成本降低60-80%

模式5: Token预算控制
  限制输入长度 + 输出长度 → 控制单次成本
```

### 6.2 成本仪表板

```
实时成本监控指标:
  - 每分钟花费 ($)
  - 每用户平均成本
  - 每模型成本分布
  - 缓存命中率 (省钱%)
  - 浪费的Token (截断/重试)
  
告警:
  - 单租户日花费 > 预算80%
  - 某模型突然用量暴增
  - 缓存命中率骤降
```

## 七、AI项目的商业模式

### 7.1 四种AI商业模式

| 模式 | 收入来源 | 代表 | 利润率 |
|------|---------|------|--------|
| **API经济** | 按调用收费 | OpenAI, Anthropic | 高(70%+) |
| **SaaS + AI** | 订阅+AI增值 | GitHub Copilot, Notion AI | 中高(60-80%) |
| **AI原生应用** | 订阅/交易 | Midjourney, Suno | 中(50-70%) |
| **AI基础设施** | 平台费/GPU租赁 | CoreWeave, Modal | 中低(30-50%) |

### 7.2 自研AI平台的商业论证

```
场景: 企业内部AI平台

投入:
  建设: $500K (2 FTEs × 6个月 + GPU)
  年运维: $300K

收益 (替代外部API):
  OpenAI API 月费: $50K → 年 $600K
  内部平台: 年 $300K
  节省: $300K/年
  
ROI: (300 - 300) / 500 = 0% (第1年)
       (600 - 300) / 500 = 60% (第2年)
       
+ 隐性收益: 数据安全, 定制能力, 不依赖外部
  
结论: 月API费 > $30K 可考虑自建
```

## 八、架构决策的经济视角

**每一次架构决策都隐含经济选择**：

| 架构决策 | 经济含义 |
|---------|---------|
| 用KV Cache vs 重算 | 存储成本 vs 计算成本 |
| Continuous Batching | GPU利用率 → 降低单位成本 |
| 微调 vs RAG | 前期投入 vs 每次推理成本 |
| 流式 vs 非流式 | 延迟 vs 吞吐（影响用户体验=收入） |
| 开源 vs API | CapEx vs OpEx |
| 一个模型 vs 多个模型 | 运维复杂度 vs 成本优化空间 |
