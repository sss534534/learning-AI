# 大模型原理与选型

> 理解不同规模模型的特点与适用场景

## 1. 大模型发展脉络

### 1.1 三代模型演进

```
第一代（2018-2020）：BERT/GPT-1/GPT-2
    ↓ 预训练+微调范式
第二代（2020-2022）：GPT-3/ChatGLM/LLaMA
    ↓ 提示工程+上下文学习
第三代（2022-至今）：GPT-4/Claude/Gemini
    ↓ 多模态+Agent+工具使用
```

### 1.2 主流模型家族

| 家族 | 代表模型 | 特点 | 开源 |
|------|----------|------|------|
| GPT | GPT-3.5/4/4o | 闭源最强，多模态 | ❌ |

## 2. 模型规模与能力

### 2.1 规模分类

**小型模型（< 10B）：端侧部署**
- 代表：LLaMA-2-7B、Qwen-7B、Phi-3-mini
- 特点：可单卡/CPU运行，延迟低
- 适用：移动端、边缘设备、简单任务

**中型模型（10B - 70B）：企业主力**
- 代表：LLaMA-2-70B、Qwen-72B、Mixtral-8x7B
- 特点：性能接近大模型，成本可控
- 适用：企业级应用、复杂推理

**大型模型（> 100B）：高端场景**
- 代表：GPT-4、Claude-3-Opus、Llama-3-400B
- 特点：最强推理能力，高成本
- 适用：研究、复杂多步任务、Agent系统

### 2.2 规模与性能关系

**Scaling Law（缩放定律）：**
```
Loss ∝ (N^(-α))  # N为参数量，α≈0.07
```

**关键洞察：**
- 模型性能随规模、数据量、计算量幂律增长
- 存在**涌现能力**（Emergent Abilities）：某些能力只在特定规模后出现
- 但边际收益递减，需权衡成本

### 2.3 涌现能力阈值

| 能力 | 大致阈值 | 说明 |
|------|----------|------|
| 上下文学习 | ~10B | 少量示例学习 |
| 思维链推理 | ~100B | CoT提示有效 |
| 指令遵循 | ~100B | 遵循复杂指令 |
| 多语言 | ~70B | 跨语言迁移 |

## 3. 模型架构变体

### 3.1 Dense vs MoE

**Dense模型（稠密）：**
- 所有参数参与每个token计算
- 代表：GPT-4、LLaMA
- 特点：简单、稳定、易部署

**MoE模型（混合专家）：**
- 每token只激活部分专家网络
- 代表：Mixtral、Switch Transformer
- 特点：参数量大但计算量小

**MoE架构详解：**
```
输入 → Router → 选择Top-K专家 → 专家输出加权 → 输出
```

**MoE优势：**
- 总参数量可达激活参数的8-16倍
- 推理成本与激活参数成正比
- Mixtral-8x7B ≈ 47B总参数，但推理成本≈13B

### 3.2 长上下文模型

**上下文长度演进：**
- 早期：2K tokens（GPT-3）
- 主流：4K-8K（GPT-3.5）
- 长上下文：32K-128K（GPT-4、Claude-3）
- 超长：1M+（Gemini 1.5 Pro）

**长上下文技术：**

| 技术 | 原理 | 代表模型 |
|------|------|----------|
| 位置编码外推 | ALiBi、NTK-aware RoPE | MPT、CodeLlama |
| 滑动窗口注意力 | 局部注意力+全局摘要 | Mistral |
| Ring Attention | 分布式注意力计算 | - |
| 压缩注意力 | 历史KV压缩 | H2O、StreamingLLM |

### 3.3 多模态模型

**架构模式：**

1. **统一编码器**（GPT-4V、Gemini）
   ```
   图像 → Vision Encoder → 与文本统一表示 → LLM
   ```

2. **投影对齐**（LLaVA、Qwen-VL）
   ```
   图像 → CLIP/ViT → Projector → 接入LLM
   ```

3. **工具调用**（早期方案）
   ```
   LLM生成描述 → 外部视觉模型处理 → 结果返回
   ```

## 4. 模型选型决策框架

### 4.1 选型维度矩阵

| 维度 | 选项 | 适用场景 |
|------|------|----------|
| **任务类型** | 文本生成 | 对话、写作、代码 |
| | 文本理解 | 分类、抽取、分析 |
| | 多模态 | 图文理解、视频分析 |
| **部署环境** | 云端API | 快速启动、弹性伸缩 |
| | 私有化部署 | 数据安全、合规要求 |
| | 端侧 | 离线场景、低延迟 |
| **成本敏感** | 高 | 选择小模型+量化 |
| | 中 | 开源模型自托管 |
| | 低 | 闭源大模型API |

### 4.2 场景化选型建议

**场景1：企业内部知识库问答**
```
推荐：Qwen-72B + RAG
理由：
- 中文场景表现好
- 72B规模推理能力足够
- 开源可私有化部署
- 配合RAG解决知识时效性
```

**场景2：代码助手**
```
推荐：CodeLlama-34B 或 GPT-4
理由：
- 代码专项训练
- 长上下文支持（16K+）
- 支持多种编程语言
```

**场景3：移动端AI助手**
```
推荐：Phi-3-mini 或 Qwen-1.8B
理由：
- 3-4B参数，端侧可运行
- 经过指令微调
- 功耗和延迟可控
```

**场景4：复杂Agent系统**
```
推荐：GPT-4 或 Claude-3-Opus
理由：
- 强推理和规划能力
- 工具使用准确率高
- 长上下文支持多轮协作
```

### 4.3 开源 vs 闭源决策树

```
是否有数据安全/合规要求？
├── 是 → 必须私有化部署
│       └── 选择开源模型（LLaMA/Qwen/ChatGLM）
└── 否 → 是否有足够GPU资源？
        ├── 是 → 自托管开源模型（成本更低）
        └── 否 → 使用闭源API（GPT-4/Claude）
```

## 5. 模型评估维度

### 5.1 基础能力评估

| 能力 | 测试方法 | 常用基准 |
|------|----------|----------|
| 推理能力 | 数学题、逻辑题 | GSM8K、MATH |
| 知识问答 | 事实性问题 | MMLU、TruthfulQA |
| 代码能力 | 编程题 | HumanEval、MBPP |
| 阅读理解 | 文本理解 | RACE、SQuAD |
| 多语言能力 | 翻译、跨语言 | XLSum、MGSM |

### 5.2 生产环境评估

**延迟指标：**
- **TTFT** (Time To First Token): 首token延迟，影响用户体验
- **TPOT** (Time Per Output Token): 生成速度，影响流畅度

**吞吐量指标：**
- **QPS**: 每秒请求数
- **Token/s**: 每秒生成token数

**资源指标：**
- **显存占用**: 模型权重 + KV Cache
- **GPU利用率**: 计算效率

### 5.3 业务效果评估

**建立业务评估集：**
```
1. 收集真实业务场景的问题
2. 人工标注理想答案
3. 设计自动化评估指标
4. 定期回归测试
```

**常用评估方法：**
- **Exact Match**: 完全匹配
- **F1 Score**: 部分匹配
- **LLM-as-Judge**: 用更强模型评估
- **人工评估**: 最终标准

### 关键问题

**Q1: 是否需要微调？**
- 通用任务：Prompt工程 + RAG
- 专业领域：领域数据微调
- 特定格式：LoRA轻量微调

**Q2: 单模型还是多模型？**
- 单模型：简单、一致性好
- 多模型：路由优化、成本可控

**Q3: 如何持续迭代？**
- 建立评估基准
- 监控生产指标
