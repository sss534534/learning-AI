## 1. Hermes Agent（Nous Research）

**GitHub ⭐：172k+** | 开源 Agent 平台领跑者

### 1.1 定位

通用型开源 Agent 平台，致力于成为"Agent 界的 Linux"——一个厂商中立、可自托管、高度可定制的 Agent 运行时。

### 1.2 核心架构

```
┌───────────────────────────────────────────────┐
│                 Hermes Agent                   │
├───────────────────────────────────────────────┤
│  ┌─────────────────────────────────────────┐  │
│  │           Agent Runtime                  │  │
│  │  · 状态管理                              │  │
│  │  · 工具执行引擎                           │  │
│  │  · 记忆系统                              │  │
│  └────────────────┬────────────────────────┘  │
│                   │                            │
│  ┌────────────────▼────────────────────────┐  │
│  │           Skill Registry                 │  │
│  │  · 技能发现 / 注册 / 版本管理            │  │
│  │  · 依赖解析                              │  │
│  └────────────────┬────────────────────────┘  │
│                   │                            │
│  ┌────────────────▼────────────────────────┐  │
│  │          Transport Layer                 │  │
│  │  · MCP（默认）                           │  │
│  │  · ACP（兼容）                           │  │
│  │  · 自定义传输                            │  │
│  └─────────────────────────────────────────┘  │
└───────────────────────────────────────────────┘
```

### 1.3 关键特性

| 特性 | 说明 |
|------|------|
| 多模型兼容 | Claude、GPT、Codex 及任意 OpenAI-compatible API |
| Skill-based | 模块化技能注册，类似"Agent 的 App Store" |
| MCP 原生 | 默认传输层，兼容 10000+ MCP Server |
| 可观测性 | 内置 tracing、token 审计、性能监控 |
| 零配置启动 | 5 分钟部署一个可用 Agent |
| 热加载 | 技能和工具无需重启即可更新 |

### 1.4 快速示例

```python
from hermes import HermesAgent, Skill

agent = HermesAgent(model="claude-opus-4")

@agent.skill
def search_web(query: str) -> str:
    """搜索互联网获取最新信息"""
    return call_search_api(query)

@agent.skill
def calculate(expr: str) -> float:
    """执行数学计算"""
    return eval(expr)

result = agent.run("搜索 2026 年 AI 市场规模并计算增长率")
```

## 2. Claude Code（Anthropic）

CLI-first 开发 Agent，2026 年发布重大升级

### 2.1 Dynamic Workflows（2026-05）

Claude Opus 4.8 的核心 Agent 能力增强：

```
传统模式：
  用户输入 → Claude 思考 → 调用工具 → 返回结果

Dynamic Workflows：
  用户输入 → Orchestrator 拆解任务
    ├── Subagent 1：搜索 API 文档（并行）
    ├── Subagent 2：读取代码库（并行）
    ├── Subagent 3：分析依赖（并行）
    └── Orchestrator 汇总结果 → 生成方案
```

### 2.2 Tool Search + Deferred Loading

```
Before: 所有工具定义一次性加载到 context
  → Context 被工具定义占满
  → Agent 只有少量 token 可用于实际推理

After: Tool Search + Deferred Loading
  → 仅加载匹配当前任务的工具
  → Context 使用减少 85%+
  → Agent 有更多 token 用于推理
```

### 2.3 内置 Agent 循环

```bash
# 使用 /code-review 进行 Agent 间代码审查
claude /code-review --pr 42 --reviewers 3

# 多 Agent 并行执行
claude /task:refactor-auth --agents 3
```

### 2.4 适用场景

- 软件工程（代码生成、重构、审查）
- CLI 自动化脚本
- CI/CD 管道集成

## 5. 开源 vs 商业框架决策

```
选择开源如果：
  ✅ 需要数据主权和控制权
  ✅ 预算敏感（按 token 计费成本高）
  ✅ 需要深度定制
  ✅ 不想绑定特定云厂商

选择商业框架如果：
  ✅ 需要托管服务和 SLA
  ✅ 团队没有运维能力
  ✅ 需要企业级合规和身份管理
  ✅ 已经在目标生态（OpenAI/Microsoft）内

## 深度分析

开源 Agent 框架（Hermes、Claude Code、OpenClaw）构成了 Agent 生态的第三极——社区驱动、自托管、可定制。

### 开源框架的隐藏成本

```
开源框架的 TCO（Total Cost of Ownership）包括：

显性成本:
  ├─ 基础设施：GPU/CPU 服务器、存储、网络（通常占比 40-60%）
  ├─ 运维人力：部署、监控、升级、故障处理（占比 20-30%）
  └─ 安全合规：审计、漏洞修复、合规认证（占比 10-20%）

隐性成本:
  ├─ 学习曲线：团队上手时间（2-4周）
  ├─ 集成成本：与现有系统打通（1-4周）
  ├─ 调试成本：开源软件的 bug 需要自己定位修复
  └─ 退役成本：切换框架时的数据迁移和重构

商业框架把这些成本打包进了 API 调用费或座位费中。
选择开源 = 接受显性成本可能低于商业方案，但隐性成本更高。

开源 vs 商业的盈亏平衡点:
  小团队（<10人）：商业框架便宜（无需运维人力）
  中型团队（10-50人）：开源更划算（分摊运维人力）
  大型企业（>50人）：开源 + 商业混合（核心自托管 + 非核心用托管）
```

### 社区健康度评估

选择开源框架就是选择它的社区。社区死亡 = 框架死亡。

```
开源 Agent 框架评估维度:

1. 贡献活跃度
   ├─ 每日 commit 数（健康：>10）
   ├─ 周活跃贡献者（健康：>20）
   └─ issue 响应时间（健康：<48h）

2. 治理结构
   ├─ 是单一公司主导还是社区治理？
   ├─ 核心维护者的数量和背景？
   └─ 路线图的决策机制（开放 RFC vs 闭门决策）？

3. 版本稳定性
   ├─ 发布频率（健康：每月一个minor）
   ├─ breaking change 的频率（警告：频繁major）
   └─ 是否有 LTS 版本策略？

4. 生态繁荣度
   ├─ 第三方插件/集成的数量和质量
   ├─ 相关工具链（可观测性、部署、测试）
   └─ 文档和教程的完整性

红牌警告:
  ⚠️ 核心贡献者突然减少
  ⚠️ 超过3个月没有发布
  ⚠️ 积压未处理的 security issue
  ⚠️ 主要维护者离职或失去兴趣
```

### 开源框架的战术使用

```
典型团队的混合策略:

        ┌─────────────────────────────────────┐
        │           Agent 系统整体            │
        ├─────────────────────────────────────┤
        │  核心能力（自托管开源）              │
        │  ├─ Hermes Agent 作为运行时         │
        │  └─ OpenClaw 插件市场加速开发       │
        ├─────────────────────────────────────┤
        │  辅助能力（商业框架托管服务）        │
        │  ├─ Claude Code 用于开发辅助        │
        │  └─ OpenAI API 作为备用模型         │
        ├─────────────────────────────────────┤
        │  基础设施层（可替换）               │
        │  ├─ MCP 协议（工具标准）            │
        │  └─ A2A 协议（通信标准）            │
        └─────────────────────────────────────┘

原则：
  - 核心容错能力：自托管，无第三方依赖
  - 非核心能力：用商业服务降低成本
  - 协议层：永远选择标准协议，不绑定框架
```

### 2026年开源 Agent 格局判断

```
市场分化趋势：
  
  Hermes → "Agent 界的 Linux"
    通用平台，厂商中立，适合自托管企业
  
  Claude Code → "Agent 界的 VS Code"  
    开发场景独占，CLI-first，适合工程团队
  
  OpenClaw → "Agent 界的 WordPress"
    插件生态最大，低代码，适合业务用户

三者的竞合关系：
  互补 > 竞争，因为场景不同
  但在通用 Agent 场景可能逐步趋同
```

开箱即用 vs 深度定制的权衡是选型的核心。Claude Code 的 CLI-first 设计对软件开发者极其友好；Hermes 的 Skill Registry 设计提供更高的可扩展性；OpenClaw 的配置可移植性和企业部署工具让它在企业用户中具有独特优势。
```
