## 1. 什么是云原生？

### 核心定义

**云原生（Cloud Native）** 是一种构建和运行应用程序的方法论，充分利用云计算优势（弹性、可扩展、高可用）。

### 云原生四层技术栈

```
云原生技术栈
├── 应用定义与开发层
│   ├── 微服务
│   ├── 服务网格
│   └── 无服务器
├── 编排与管理层
│   ├── Kubernetes
│   └── 多集群管理
├── 运行时层
│   ├── 容器运行时
│   ├── 云原生存储
│   └── 云原生网络
└── 基础设施层
    ├── 公有云
    ├── 私有云
    └── 混合云
```

### 为什么选择云原生？

| 传统方式 | 云原生方式 | 优势 |
|---------|----------|------|
| 手动配置 | Infrastructure as Code | 可重复、可审计 |
| 单体应用 | 微服务架构 | 独立部署、弹性扩展 |
| 物理服务器 | 容器化部署 | 一致环境、快速交付 |
| 周期性发布 | 持续交付 | 快速迭代、快速反馈 |

## 2. Hello Kubernetes：你的第一个云原生应用

### 2.1 环境准备（5分钟）

```bash
# 1. 安装 Docker (桌面版)
# 下载地址: https://www.docker.com/get-started

# 2. 启用 Kubernetes (Docker Desktop)
# Settings → Kubernetes → Enable Kubernetes

# 3. 验证安装
kubectl version
kubectl get nodes  # 应该看到一个节点
```

### 2.2 部署第一个应用（10分钟）

```yaml
# hello-k8s.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: hello-k8s
spec:
  replicas: 3
  selector:
    matchLabels:
      app: hello-k8s
  template:
    metadata:
      labels:
        app: hello-k8s
    spec:
      containers:
      - name: hello
        image: nginx:alpine
        ports:
        - containerPort: 80

---
apiVersion: v1
kind: Service
metadata:
  name: hello-k8s
spec:
  type: NodePort
  selector:
    app: hello-k8s
  ports:
  - protocol: TCP
    port: 80
    targetPort: 80
    nodePort: 30080
```

```bash
# 部署应用
kubectl apply -f hello-k8s.yaml

# 查看部署状态
kubectl get deployments
kubectl get pods

# 访问应用
# 浏览器打开: http://localhost:30080
```

### 2.3 扩容与自愈（5分钟）

```bash
# 扩容到5个副本
kubectl scale deployment hello-k8s --replicas=5

# 查看Pod状态
kubectl get pods -w

# 模拟故障 - 删除一个Pod
kubectl delete pod <pod-name>

# Kubernetes会自动创建新的Pod！
```

## 3. 核心概念速查表

### 3.1 容器 vs 虚拟机

| 特性 | 容器 | 虚拟机 |
|------|------|-------|
| 隔离级别 | 进程级 | 硬件级 |
| 启动时间 | 秒级 | 分钟级 |
| 资源占用 | 轻量 | 较重 |
| 镜像大小 | MB级 | GB级 |
| 一致性 | 高 | 中 |

### 3.2 Kubernetes核心概念

| 概念 | 说明 |
|------|------|
| **Pod** | 最小调度单元，包含一个或多个容器 |
| **Deployment** | 声明式应用管理，负责Pod的部署和扩缩容 |
| **Service** | 服务发现与负载均衡 |
| **ConfigMap/Secret** | 配置管理，解耦配置与应用 |
| **Ingress** | 入口流量管理 |
| **Namespace** | 资源隔离与多租户 |

### 3.3 架构设计原则

| 原则 | 说明 |
|------|------|
| **单一职责** | 每个组件只负责一件事 |
| **高内聚低耦合** | 内部紧密相关，外部松耦合 |
| **面向失败设计** | 假设失败会发生，主动应对 |
| **可观测性** | 能够了解系统内部状态 |
| **自动化一切** | 减少人工干预，提高效率 |

## 5. 常见问题FAQ

### Q1：需要先学什么基础？

**回答**：
- 必备：Linux基础、网络基础
- 推荐：一门编程语言（Go/Python/Java）
- 加分：云服务使用经验

### Q2：容器和虚拟机的区别？

**简单理解**：
- **容器**：共用宿主机内核，轻量，秒级启动
- **虚拟机**：完整操作系统，较重，分钟级启动

### Q3：Kubernetes难吗？

**回答**：
- 入门简单：掌握核心概念即可开始使用
- 精通需要时间：生产级部署需要深入学习
- 建议循序渐进：从单机开始，逐步扩展

### Q4：选择哪个云平台？

| 场景 | 推荐 |
|------|------|
| **学习/实验** | AWS/GCP/Azure免费额度 |
| **国内开发** | 阿里云/腾讯云 |
| **企业生产** | 按需选择，考虑成本与合规 |

### Q5：如何找实战项目？

**建议**：
1. 从简单应用开始（博客、待办、API）
2. 逐步增加复杂度（加数据库、消息队列）
3. 参与开源项目
4. 工作中寻找微服务改造机会
