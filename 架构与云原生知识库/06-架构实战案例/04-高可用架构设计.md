# 高可用架构设计

> 高可用（High Availability）指系统在面对故障时仍能持续提供服务的能力，通常用 SLA 衡量。

---

## 1. 可用性层级

| 可用性 | 年停机时间 | 俗称 |
|--------|-----------|------|
| 99% | 87.6小时 | 2个9 |
| 99.9% | 8.76小时 | 3个9 |
| 99.99% | 52.56分钟 | 4个9 |
| 99.999% | 5.26分钟 | 5个9 |
| 99.9999% | 31.5秒 | 6个9 |

## 2. 高可用策略

### 2.1 消除单点故障

| 层级 | 策略 | 实现 |
|------|------|------|
| 网络 | 多AZ部署 | Active-Active |
| 计算 | 多副本 | 负载均衡 |
| 存储 | 数据复制 | 主从/多副本 |
| 应用 | 无状态设计 | 水平扩展 |
| 数据库 | 主从/多活 | 读写分离 |

### 2.2 故障转移

```
主 → 健康检查失败 → 备用接管 → 恢复后重新同步
```

### 2.3 容量冗余

**N+1 冗余：**
- N：所需容量
- +1：冗余容量
- 例：3个节点可支撑峰值，部署4个

---

## 3. 灾备架构

| 模式 | RPO | RTO | 成本 |
|------|-----|-----|------|
| 备份恢复 | 24h | 4h+ | 低 |
| 主从+异地 | 1s-5min | 1-15min | 中 |
| 双活 | 0 | 0-1min | 高 |
| 三地五中心 | 0 | 0 | 极高 |

**RPO：** 最多丢失多久数据  
**RTO：** 多久恢复服务

---

## 4. 实战最佳实践

- 所有依赖都假设会失败 → 断路器 + 超时 + 重试
- 冗余单元独立故障 → 避免级联故障
- 混沌工程 → 主动注入故障验证
- 容量规划 → 峰值2倍冗余
