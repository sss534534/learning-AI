# 云原生改造实战

> 将传统应用改造为云原生架构，利用容器化、Kubernetes、微服务和DevOps提升交付效率和运维能力。

---

## 1. 改造评估

| 维度 | 传统架构 | 云原生 |
|------|---------|--------|
| 部署 | 物理机/VM | 容器 |
| 扩展 | 垂直扩展 | 水平扩展 |
| 发布 | 停机发布 | 滚动更新 |
| 配置 | 配置文件 | 环境变量/ConfigMap |
| 日志 | 文件 | stdout + 采集 |
| 健康 | 无 | 探针 |

## 2. 改造步骤

```
容器化 → 编排 → 微服务化 → 服务网格 → GitOps
```

### 2.1 容器化评估

```dockerfile
# 从传统部署到容器化
FROM openjdk:17-slim
COPY target/app.jar /app.jar
EXPOSE 8080
HEALTHCHECK --interval=30s --timeout=3s \
  CMD curl -f http://localhost:8080/health || exit 1
ENTRYPOINT ["java", "-jar", "/app.jar"]
```

### 2.2 渐进式容器化

1. **提升（Lift & Shift）**：直接容器化，不改代码 ✅ 快速
2. **重构**：拆分有状态/无状态 ✅ 收益大
3. **重写**：完全重写 ⚠️ 高成本

## 3. 常见问题

| 问题 | 解决方案 |
|------|---------|
| 本地文件存储 | 改为对象存储/S3 |
| 会话本地化 | Redis外部存储 |
| 定时任务冲突 | 分布式锁+Leader选举 |
| 日志查看 | ELK/Loki集中式日志 |
| 配置修改 | 配置中心+热加载 |
