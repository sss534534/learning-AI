# 领域驱动设计

> 领域驱动设计（DDD）将复杂业务系统的核心建模放在首位，通过通用语言、限界上下文和战术模式，确保软件设计精准反映业务需求。

## 1. DDD核心概念

### 1.1 通用语言

所有团队成员（业务+技术）使用统一语言沟通——体现在代码、文档、讨论中。

### 1.2 限界上下文

每个模型都有明确的边界——内部概念在外部无意义。

### 1.3 领域、子域、核心域

| 类型 | 描述 | 策略 |
|------|------|------|
| 核心域 | 核心竞争力 | 自研，最大投入 |
| 支撑域 | 必要但不核心 | 自研或外包 |
| 通用域 | 通用能力 | 采购或使用开源 |

## 2. 战略设计

### 2.1 上下文映射

| 关系 | 描述 | 图示 |
|------|------|------|
| 合作关系 | 双方同步演进 | `[A] ↔ [B]` |
| 客户-供应商 | 上游决定下游 | `[A] → [B]` |
| 防腐层 | 下游保护自己 | `[A] → ACL → [B]` |
| 开放主机 | 提供明确API | `[A] → OHS → [B]` |

### 2.2 防腐层（ACL）

防止外部模型污染内部核心领域：

```python
# 外部系统模型
class ExternalUserDTO:
    def __init__(self, data):
        self.id = data['user_id']
        self.full_name = data['name']

# 内部领域模型
class User:
    def __init__(self, user_id, name):
        self.user_id = user_id
        self.name = name

# 防腐层适配
class ExternalUserAdapter:
    def to_domain(self, external: ExternalUserDTO) -> User:
        return User(
            user_id=external.id,
            name=external.full_name
        )
```

## 3. 战术设计

### 3.1 实体（Entity）

有唯一标识，生命周期内身份不变：

```python
class Order:
    def __init__(self, order_id: str):
        self.id = order_id  # 唯一标识
        self.status = "PENDING"
        self.items = []

    def add_item(self, product_id: str, quantity: int):
        self.items.append(OrderItem(product_id, quantity))
```

### 3.2 值对象（Value Object）

无标识，由属性定义：

```python
@dataclass(frozen=True)
class Address:
    street: str
    city: str
    zip_code: str
    country: str
```

### 3.3 聚合（Aggregate）

一致性边界——外部只能通过聚合根操作：

```
Order（聚合根）
├── OrderItem（实体）
├── ShippingAddress（值对象）
└── PaymentInfo（值对象）
```

**规则：** 一次事务只修改一个聚合。

### 3.4 领域服务

处理不属于实体/值对象的业务逻辑：

```python
class PricingService:
    def calculate_discount(self, order: Order, user: User) -> Money:
        if user.is_vip and order.total > 1000:
            return order.total * 0.9
        return order.total
```

### 3.5 仓库（Repository）

聚合的存储抽象：

```python
class OrderRepository(ABC):
    @abstractmethod
    def save(self, order: Order): ...
    @abstractmethod
    def find_by_id(self, order_id: str) -> Order: ...
```

### 3.6 领域事件

表示领域中发生的重要事情：

```python
@dataclass
class OrderPlaced:
    order_id: str
    user_id: str
    total: Money
    occurred_at: datetime
```

## 4. DDD与微服务

### 4.1 限界上下文 → 微服务

```
限界上下文1: 订单 → Order Service
限界上下文2: 库存 → Inventory Service
限界上下文3: 支付 → Payment Service
```

每个微服务内部DDD战术模式完整，服务间通过事件通信。

### 4.2 演进式架构

DDD不是为了微服务而存在——单体内部也可以使用DDD战术模式，在需要时自然演进出服务边界。

## 5. 事件风暴

### 5.1 工作坊形式

```
参与：业务专家 + 技术团队
过程：贴便签 → 识别事件 → 建立流程 → 划分边界
产出：领域事件流 + 限界上下文
```

### 5.2 事件风暴基础元素

| 元素 | 颜色 | 含义 |
|------|------|------|
| 领域事件 | 🟠 | 已发生的业务事件 |
| 命令 | 🔵 | 触发事件的指令 |
| 聚合 | 🟢 | 一致性边界 |
| 外部系统 | 🟣 | 集成接口 |
| 用户 | 🟡 | 角色/参与者 |
