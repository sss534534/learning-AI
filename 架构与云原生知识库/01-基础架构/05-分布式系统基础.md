## 1. 分布式系统特性

### 1.1 八大谬误

> Peter Deutsch 提出的分布式系统设计者常犯的假设：

1. 网络可靠 — ❌ 网络会断
2. 延迟为零 — ❌ 网络延迟显著
3. 带宽无限 — ❌ 带宽有限
4. 网络安全 — ❌ 网络不安全
5. 拓扑不变 — ❌ 机器增减
6. 只有一个管理员 — ❌ 多团队
7. 传输成本为零 — ❌ 序列化/反序列化
8. 网络同质 — ❌ 异构网络

### 1.2 分布式系统目标

| 目标 | 说明 | 实现方式 |
|------|------|---------|
| 可扩展性 | 增加节点提升性能 | 水平扩展 |
| 可用性 | 部分故障不影响整体 | 冗余+故障转移 |
| 一致性 | 所有节点数据一致 | 共识算法 |
| 分区容错 | 网络分区可运行 | CAP权衡 |

## 2. 一致性模型

### 2.1 一致性强度谱系

```
严格一致性 < 线性一致性 < 顺序一致性 < 因果一致性 < 最终一致性
（越左越强，越右越可用）
```

| 模型 | 描述 | 系统示例 |
|------|------|---------|
| 线性一致性 | 操作实时排序，像单机 | 分布式锁(ZK) |
| 顺序一致性 | 操作按程序顺序，节点间可能延迟 | 分布式DB |
| 因果一致性 | 有因果关系的操作有序 | CRDT |
| 最终一致性 | 无更新后最终一致 | DNS，CDN |

### 2.2 Quorum机制

**公式：**
- 读成功：$R + W > N$（W：写副本数，R：读副本数，N：总副本数）
- 写成功：$W > N/2$

**场景：**
- 强一致：$W = N, R = 1$（写所有）
- 高可用：$W = 1, R = N$（读所有）
- 平衡：$W = R = N/2 + 1$（多数）

## 3. 共识算法

### 3.1 Paxos vs Raft

| 维度 | Paxos | Raft |
|------|-------|------|
| 理解难度 | 高（学术界） | 低（工业界标准） |
| 领导人 | 多角色，不固定 | 显式选举Leader |
| 日志复制 | 两阶段 | 日志按Leader索引 |
| 成员变更 | 复杂 | Joint Consensus |

### 3.2 Raft 核心流程

```
Leader选举 → 日志复制 → 安全性保证
    ↓                          ↑
  Term/count        ←  多数节点确认
```

```python
# Raft 状态简化示意
class RaftNode:
    def __init__(self):
        self.state = 'FOLLOWER'  # FOLLOWER | CANDIDATE | LEADER
        self.current_term = 0
        self.log = []
        self.commit_index = 0
```

### 3.3 应用场景

| 系统 | 算法 | 用途 |
|------|------|------|
| etcd | Raft | 服务发现，配置中心 |
| Consul | Raft | 服务网格 |
| Zookeeper | ZAB (类Paxos) | 分布式协调 |
| TiDB | Raft | 分布式事务 |

## 4. 分布式存储

### 4.1 数据复制策略

| 策略 | 描述 | 优缺点 |
|------|------|--------|
| 主从复制 | 主写从读 | 写瓶颈，从延迟 |
| 多主复制 | 多节点写 | 冲突处理复杂 |
| 无主复制 | 分散写 | 最终一致，需调停 |

### 4.2 分区策略

| 策略 | 描述 | 适用 |
|------|------|------|
| 范围分区 | 连续key分片 | 范围查询 |
| 哈希分区 | hash取模 | 负载均衡 |
| 一致性哈希 | 环状分布 | 动态扩缩 |

### 4.3 GFS/HDFS架构

```
Client
  ↓ 读/写请求
Master (NameNode) → 元数据管理
  ↓ 分块位置
Chunk Servers (DataNodes) → 数据存储（3副本）
```

## 5. 分布式计算

### 5.1 MapReduce

```python
# MapReduce 词频统计
def map(line):
    for word in line.split():
        emit(word, 1)

def reduce(word, counts):
    emit(word, sum(counts))
```

### 5.2 流式计算 vs 批处理

| 维度 | 批处理 | 流处理 |
|------|--------|--------|
| 数据范围 | 有界 | 无界 |
| 延迟 | 分钟级 | 毫秒级 |
| 框架 | Spark, Hive | Flink, Kafka Streams |
| 状态 | 无状态 | 有状态 |
| 一致性 | exactly-once | exactly-once难 |

## 6. 分布式通信

### 6.1 RPC框架对比

| 框架 | 协议 | 序列化 | 特点 |
|------|------|--------|------|
| gRPC | HTTP/2 | Protobuf | 跨语言，双向流 |
| Thrift | TCP | Thrift | 高性能，紧凑 |
| Dubbo | TCP | Hessian | Java生态 |
| tRPC | HTTP/2 | Protobuf/Flatbuffers | 腾讯 |

### 6.2 消息队列对比

| 系统 | 模型 | 持久化 | 顺序保证 | 适用场景 |
|------|------|--------|----------|---------|
| Kafka | 发布订阅 | 磁盘 | 分区内有序 | 日志/事件流 |
| RabbitMQ | AMQP | 内存+磁盘 | 单队列有序 | 任务队列 |
| Pulsar | 发布订阅 | 分层存储 | 分区有序 | 多租户 |
| RocketMQ | 发布订阅 | 磁盘 | 分区有序 | 金融 |

### 6.3 分布式链路追踪

**核心概念：**
- Trace：一次请求的完整链路
- Span：链路中的单个操作
- Context Propagation：上下文传播

```python
# OpenTelemetry 示例
from opentelemetry import trace

tracer = trace.get_tracer(__name__)
with tracer.start_as_current_span("handle_request") as span:
    span.set_attribute("user_id", "123")
    result = process_request()
```
