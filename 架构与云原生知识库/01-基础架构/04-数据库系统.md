## 1. 数据库分类与选型

### 1.1 数据库类型图谱

| 类型 | 代表 | 适用场景 |
|------|------|---------|
| 关系型 | PostgreSQL, MySQL | OLTP，强一致性 |
| 文档型 | MongoDB, Couchbase | 灵活Schema，JSON |
| 键值型 | Redis, DynamoDB | 缓存，会话存储 |
| 宽表型 | Cassandra, HBase | 时序，IoT |
| 图数据库 | Neo4j, Dgraph | 关系分析，推荐 |
| 时序库 | InfluxDB, TimescaleDB | 监控指标 |
| 搜索引擎 | Elasticsearch | 全文检索，日志 |

### 1.2 选型决策矩阵

```
业务需求
├── 关系复杂 → 关系型/图数据库
├── 高并发读写 → Redis/Cassandra
├── 灵活Schema → MongoDB
├── 全文搜索 → Elasticsearch
├── 时序指标 → InfluxDB
└── 强事务保证 → PostgreSQL/MySQL
```

## 2. 关系型数据库

### 2.1 SQL执行流程

```
SQL → 解析器 → 优化器 → 执行器 → 存储引擎 → 磁盘
                ↓
           查询计划
```

### 2.2 范式

| 范式 | 要求 | 说明 |
|------|------|------|
| 1NF | 列不可分 | 原子性 |
| 2NF | 部分依赖消除 | 联合主键下 |
| 3NF | 传递依赖消除 | 非主属性不依赖其他非主属性 |
| BCNF | 所有决定因素都是候选键 | 更严格的3NF |

### 2.3 JOIN操作原理

```sql
-- Nested Loop Join：驱动表小结果集时高效
SELECT * FROM users u JOIN orders o ON u.id = o.user_id;

-- Hash Join：大表等值连接
-- Merge Join：排序数据连接
```

## 3. 事务与ACID

### 3.1 ACID

| 特性 | 含义 | 实现机制 |
|------|------|---------|
| 原子性 | 全部成功或全部回滚 | Undo Log |
| 一致性 | 事务前后数据一致 | 应用层+约束 |
| 隔离性 | 并发事务互不干扰 | MVCC/锁 |
| 持久性 | 提交后永久保存 | Redo Log |

### 3.2 隔离级别

| 级别 | 脏读 | 不可重复读 | 幻读 | 性能 |
|------|------|------------|------|------|
| 读未提交 | ❌ | ❌ | ❌ | 最高 |
| 读已提交 | ✅ | ❌ | ❌ | 高 |
| 可重复读 | ✅ | ✅ | ❌ | 中 |
| 串行化 | ✅ | ✅ | ✅ | 低 |

### 3.3 MVCC原理

多版本并发控制（MVCC）通过维护数据行的多个版本实现读不阻塞写：

```
每个事务可以看到自己的快照
SELECT：只读取<=当前事务ID的版本
UPDATE：创建新版本，旧版本保留
DELETE：标记删除版本
```

## 4. 索引原理

### 4.1 B+树索引

```
         [根节点]  (内部节点存key+指针)
        /    |    \
   [内节点] [内节点] [内节点]  (内部节点)
    / |    / |    / |
  [叶] [叶] [叶] [叶] [叶] [叶]  (叶子节点存数据+双向链表)
```

**特点：**
- 所有数据在叶子节点
- 叶子节点双向链表，支持范围查询
- 高度通常2-4层，百万级数据3次I/O

### 4.2 索引策略对比

| 索引类型 | 特点 | 适用 |
|---------|------|------|
| B+树 | 范围查询优秀 | 大部分场景 |
| 哈希 | 等值查询O(1) | 精确匹配 |
| 全文 | 分词+倒排 | 文本搜索 |
| 空间 | R树/GiST | 地理坐标 |
| 位图 | 低基数列 | 数仓分析 |

### 4.3 执行计划分析

```sql
EXPLAIN ANALYZE
SELECT * FROM orders WHERE user_id = 100;
-- 关注：Seq Scan vs Index Scan, 预估行数, 实际耗时
```

## 5. NoSQL数据库

### 5.1 CAP定理

```
          CP (一致性+分区容错)
         /  \
    CA /      \ AP (可用性+分区容错)
      /        \
  (一致+可用)    (可用+分区容错)
```

分布式系统中，**网络分区不可避免**，实际是CP vs AP的选择：

| 选择 | 系统 | 场景 |
|------|------|------|
| CP | HBase, ZK, etcd | 配置中心，强一致 |
| AP | Cassandra, DynamoDB | 高可用，最终一致 |

### 5.2 BASE理论

- **Basically Available**：基本可用
- **Soft State**：软状态（中间状态）
- **Eventually Consistent**：最终一致

## 6. 分布式数据库

### 6.1 分片策略

| 策略 | 描述 | 问题 |
|------|------|------|
| 范围分片 | 按key范围分 | 热点，数据倾斜 |
| 哈希分片 | hash(key) mod N | 扩缩容需rehash |
| 一致性哈希 | 环状映射，最小迁移 | 虚拟节点优化负载 |

### 6.2 分布式事务

| 方案 | 一致性 | 性能 | 复杂度 |
|------|--------|------|--------|
| 2PC | 强一致 | 低 | 中 |
| TCC | 最终一致 | 中 | 高 |
| Saga | 最终一致 | 高 | 中 |
| 消息最终一致 | 最终一致 | 高 | 低 |

### 6.3 常见分布式数据库

| 系统 | 类型 | 特点 |
|------|------|------|
| TiDB | NewSQL | MySQL兼容，水平扩展 |
| CockroachDB | NewSQL | PostgreSQL兼容，强一致 |
| Vitess | MySQL中间件 | 分片+读写分离 |
| YugabyteDB | NewSQL | 兼容多种SQL |
