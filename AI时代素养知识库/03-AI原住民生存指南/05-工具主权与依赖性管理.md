# 工具主权与依赖性管理

## 核心原则

```
用 AI 但不依赖 AI
```
- **依赖的边界**：依赖 AI 的输出速度，而非依赖 AI 的思维方式
- **保持能力**：脱离工具也能完成核心工作
- **控制权在你**：工具是租的，不是买的——随时准备切换

## 锁定风险评估框架

```
锁定风险 = 切换成本 × 数据可迁移性 × 社区生态依赖
```

| 维度 | 说明 | 低风险 | 高风险 |
|------|------|--------|--------|
| **切换成本** | 放弃该工具损失的时间/数据/习惯 | ≤ 1 天能适应 | ≥ 1 月才能适应 |
| **数据可迁移性** | 你的数据能否带走并用于其他工具 | 开放格式（Markdown/JSON） | 专有格式/无导出 |
| **社区生态依赖** | 没有该工具的周边生态能否生存 | 独立可用 | 插件/社区是核心价值 |

### 具体工具评估

| 工具 | 切换成本 | 数据可迁移性 | 生态依赖 | 总风险 | 建议 |
|------|---------|-------------|---------|-------|------|
| ChatGPT | 中（需适应对话风格） | 高（对话可导出、API 兼容） | 中（GPTs、插件） | **中** | 可用但留有备选 |
| Claude | 中（需适应 Projects） | 中（Projects 内容可导出） | 低（生态较小） | **中低** | 风险可控 |
| GitHub Copilot | 高（深度集成 IDE） | 低（无用户数据） | 中（依赖 IDE） | **中** | 注意切换成本 |
| VS Code | 高（插件生态、配置、快捷键） | 高（配置文件 Settings Sync） | 高（社区插件） | **高** | 核心工具，值得深度投资 |
| Obsidian | 低（纯本地文件） | 极高（纯 Markdown） | 低（插件可选） | **极低** | 数据主权典范 |
| Notion | 中（数据库结构） | 中（导出含格式损失） | 中（模板生态） | **中高** | 注意数据迁移策略 |
| Cursor | 中（AI 功能深度集成） | 中（基于 VS Code） | 中（AI 特性） | **中** | 依赖 AI 特性而非编辑器本身 |

## 工具独立性实践

### 1. 定期脱 AI 训练

- **频率**：每周至少一次，选择核心任务完全不用 AI
- **目的**：保持核心能力的"肌肉记忆"
- **方法**：写作、编码、分析——先用自己的能力完成，再对比 AI 的做法

### 2. 先思考，再 AI

对于关键决策流程：

```
❌ 错误模式：先问 AI → 再修改 → 直接使用
   （你的思维被 AI 的框架绑架了）
✅ 正确模式：先自己思考 → 记录思路 → 用 AI 验证/补充
   （AI 是校验工具，不是思考起点）
```

### 3. 学习底层原理

- 学**概念**（什么是 Transformer），不学**操作**（怎么用 ChatGPT）
- 学**原则**（如何评估模型质量），不学**快捷键**（哪个工具怎么用）
- 学**架构**（RAG 是怎么工作的），不学**配置**（某个平台怎么设置）

> 底层原理每 3-5 年才更新一次，工具操作每 3-6 个月就变一次。

### 4. 使用开放格式

| 数据类型 | 推荐格式 | 原因 |
|---------|---------|------|
| 笔记/文章 | Markdown | 任何编辑器可读，Git 友好，转换成本极低 |
| 结构化数据 | JSON / SQLite | 跨语言/跨平台，标准解析库丰富 |
| 配置文件 | YAML / TOML | 人类可读，版本控制友好 |
| 知识图谱 | Markdown + 双向链接 | Obsidian/Logseq 都可读，纯文本 |

**避免**：专有格式（.notion、.docx 中的复杂格式）

## 个人策略总结

```
┌─────────────────────────────────────────────┐
│             工具主权策略                      │
├─────────────────────────────────────────────┤
│  1. 把 AI 工具当作"租的"，不是"买的"         │
│     → 随时准备切换，不做深度绑定              │
│                                              │
│  2. 投资 transferable skills                 │
│     → 验证能力、分解能力、判断力              │
│     → 这些跟任何具体工具无关                  │
│                                              │
│  3. 保持"无 AI"工作流副本                    │
│     → 即使 AI 不可用，核心产出不受影响        │
│     → 这是你的"离线生存能力"                  │
│                                              │
│  4. 定期重新评估工具栈                        │
│     → 每季度做一次锁定风险评估                │
│     → 新工具出现时，不急于迁移                │
│                                              │
│  5. 数据主权至上                              │
│     → 你的所有数据应该能一键打包带走           │
│     → 如果不能，那就是风险                     │
└─────────────────────────────────────────────┘
```

### 一季度一次的"健康检查"

- [ ] 如果我今天失去所有 AI 工具，我的工作效率会下降多少？
- [ ] 过去 3 个月，我有没有学到新的 transferable skill？
- [ ] 我的数据是否全部可导出为开放格式？
- [ ] 我有没有新的工具依赖没有评估过？
- [ ] 我的"无 AI 工作流"还能正常运行吗？
