# AI 协作方法论

## AI 协作标准工作流

```
定义目标                   任务分解                   AI 执行
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│ 明确你想要   │    │ 把大任务拆   │    │ AI 逐块执行  │
│ 什么产出     │ →  │ 成小块，     │ →  │ 你的 prompt  │
│ 质量标准     │    │ 排序依赖     │    │ 决定质量     │
│ 约束条件     │    │ 定义输入输出  │    │              │
└──────────────┘    └──────────────┘    └──────────────┘
       ▲                                       │
       │                                       ▼
┌──────────────┐    ┌──────────────┐           │
│ 反馈循环     │ ←  │ 人类判断     │ ←─────────┘
│ 迭代逼近     │    │ 验证质量     │
│ 积累经验     │    │ 修正方向     │
└──────────────┘    └──────────────┘
```

### 每个阶段的检查点

| 阶段 | 核心问题 | 常见错误 |
|------|---------|---------|
| 定义目标 | "我要交付什么？验收标准是什么？" | 目标模糊就开始，结果反复返工 |
| 任务分解 | "哪些步骤可以并行？哪些依赖 AI？" | 一步到位让 AI 生成全部，质量失控 |
| AI 执行 | "我的 prompt 是否清晰、有上下文、有约束？" | prompt 太短或太笼统 |
| 人类判断 | "AI 的输出对吗？符合我的标准吗？" | 跳过验证直接使用 |
| 反馈循环 | "这次 iteration 靠近目标了吗？学到了什么？" | 给模糊反馈，AI 无法修正 |

## 超越 Prompt 工程的核心能力

### 1. 验证能力

**事实核查三角：**

```
       你已有的知识
          /\
         /  \
        /    \
       /______\
  AI 输出     外部来源（文档/数据/权威信息）
```

对 AI 输出的每一条"事实"，至少在三角中的两个角交叉验证。

**逻辑一致性检查清单：**
- [ ] AI 的结论是否基于它提供的证据？
- [ ] 有没有隐藏的假设未经检验？
- [ ] 推理链条有没有断裂？
- [ ] 有没有循环论证？
- [ ] AI 是否混淆了相关性和因果性？

### 2. 分解能力

把复杂任务拆成 AI 可以处理的小块。

**例子：写一篇 AI 架构分析文章**

```
❌ 错误做法："帮我写一篇 AI 架构文章"（太模糊）
✅ 正确做法：
   Step 1: "请列出 AI 架构分析文章的大纲，涵盖趋势、挑战、解决方案"
   Step 2: "展开【趋势】部分，每点给 2-3 个具体例子"
   Step 3: "检查展开后的内容：有没有互相矛盾的地方？"
   Step 4: "整合全文，检查逻辑流畅性和深度"
```

**分解原则：** 每个 subtask 应该能在 1-2 次对话中完成，有明确的输入和输出。

### 3. 上下文管理能力

给 AI 足够但不超量的上下文。

| 场景 | 推荐上下文 | 太多/太少的表现 |
|------|-----------|----------------|
| 代码生成 | 相关文件 + 技术栈说明 + 约束条件 | 太少：生成偏离需求；太多：关键指令被稀释 |
| 写作辅助 | 目标读者 + 风格要求 + 关键要点 | 太少：泛泛而谈；太多：AI 输出失去重点 |
| 分析任务 | 数据范围 + 分析维度 + 期望输出格式 | 太少：分析不深入；太多：AI 陷入细节 |

**使用 Structured Output（结构化输出）**：
- 用 JSON/Markdown 表格等格式约束输出结构
- 让 AI 按字段/步骤输出，便于后续处理
- 例："输出格式：{问题, 分析, 结论, 置信度}"

### 4. 反馈设计能力

给 AI 有效的修正反馈，迭代逼近目标。

**有效反馈 vs 无效反馈：**

| 无效反馈 | 有效反馈 |
|---------|---------|
| "这个不够好" | "第三段的论点缺乏数据支撑，请补充 2025 年的行业数据" |
| "再改改" | "风格从学术改为通俗，目标读者是技术管理者" |
| "不对" | "结论部分与第二段的分析矛盾，请重新推理" |

## Anti-pattern 清单

| Anti-pattern | 表现 | 后果 | 对策 |
|-------------|------|------|------|
| 盲目信任 | 不经验证直接使用 AI 输出 | 传播错误信息，损害专业信誉 | 强制自己先验证后发布，建立一个 check-list |
| 过度依赖 | 没有 AI 就不干活了，失去独立能力 | 能力退化，失去核心竞争力 | 关键任务先自己尝试，AI 只做辅助 |
| 提示过载 | 在 prompt 里塞太多指令和信息 | AI 注意力被稀释，关键要求被忽略 | 分步执行，一次一个目标，循序渐进 |
| 上下文碎片 | 每次开新对话，AI 没有历史记忆 | 重复工作，无一致性，效率低下 | 善用 Projects 知识库/长上下文，维护对话连续性 |
| 假设对齐 | 假设 AI 和你"想的是一回事" | 输出偏离预期，多次返工 | 要求 AI 先复述你的需求，确认理解一致 |

## AI 协作成熟度模型

| 级别 | 名称 | 特征 | 工作方式 |
|------|------|------|---------|
| L1 | 新手 | 单轮对话、直接使用、不加验证 | AI 问一句我答一句，拿到结果就用 |
| L2 | 熟练 | 多轮迭代、分解任务、基本验证 | 会拆任务，会迭代，会对关键点做检查 |
| L3 | 专家 | 系统化工作流、Agent 编排、结构化输出、自动化验证 | 设计可复用的工作流，用 AI 管理 AI |
| L4 | 大师 | 构建 AI 工具赋能他人、设计 AI 协作范式 | 不只自己会用，还能设计工具和流程让更多人用好 AI |

### 自评

你目前在哪个级别？每个级别的升级条件是：
- L1→L2：学会任务分解 + 验证
- L2→L3：学会工作流设计 + Agent 编排
- L3→L4：开始为他人设计工具和流程
