# 批判性思维 2.0：AI 时代的事实核查

## AI 时代批判性思维的升级

**传统批判性思维**的核心问题是："这个信息来源可靠吗？"
- 作者是谁？有什么偏见？
- 发表渠道权威吗？
- 有数据支撑吗？

**AI 时代的批判性思维**面临全新挑战：AI 的输出**总是看起来很可信**。
- 流畅自然的语言 → 削弱你的警惕
- 自信肯定的语调 → 掩盖不确定性
- 引用/格式合规 → 制造专业幻觉

**核心转变：**

| 传统问题 | AI 时代新问题 |
|---------|-------------|
| 这个信息可靠吗？ | 这个**推理过程**合理吗？ |
| 来源权威吗？ | 模型的训练数据分布适合这个问题吗？ |
| 有证据吗？ | "证据"是模型生成的还是真实存在的？ |
| 作者怎么知道的？ | 模型是"知道"还是在"预测"？ |

## AI 幻觉的根源与识别模式

### 根源

AI 的本质是**统计预测**，不是**事实检索**：

```
你问： "2024 年诺贝尔物理学奖得主是谁？"
模型处理： 把问题映射到向量空间 → 生成最可能的下一个 token 序列
          ← 这不是"查询数据库"，而是"预测最连贯的回答"
```

当训练数据中关于某个主题的 pattern 强而一致时，输出准确。当 pattern 稀疏或冲突时，模型用"最流畅的虚构"填补。

### 高发幻觉场景

| 场景 | 风险等级 | 原因 |
|------|---------|------|
| 具体数字/日期 | ⭐⭐⭐ | 精确数字在统计分布中是稀疏点 |
| 引用/参考文献 | ⭐⭐⭐ | 模型会生成"格式正确但不存在"的引用 |
| 最新事件（<= 训练截止） | ⭐⭐⭐ | 知识边界外的平滑外推 |
| 长推理链 | ⭐⭐ | 每步误差累积，最后结论可能完全偏离 |
| 小众/专业领域 | ⭐⭐ | 训练数据中 signal 弱于 noise |
| 常见知识 | ⭐ | 数据密集，统计 pattern 稳定 |

### 识别模式

| 可疑信号 | 说明 |
|---------|------|
| 过度自信的表述 | "毫无疑问"、"显然"——真实专家更常使用限定词 |
| 模糊引用 | "研究表明..."（不给出具体研究） |
| 循环论证 | 用结论证明前提，或用同义反复填充逻辑空白 |
| 完美一致性 | 真实世界的知识充满矛盾，太完美的回答常常是虚构的 |
| 异常的具体性 | "72.3% 的用户..."——在非统计语境下的精确数字通常是幻觉 |

## 三阶验证框架

```
输入：AI 输出
           │
    ┌──────▼──────┐
    │  L1 内部一致性 │ ← 不通过 → 标记为"存疑"，要求 AI 重新推理
    │    检查       │
    └──────┬──────┘
           │ 通过
    ┌──────▼──────┐
    │  L2 事实交叉  │ ← 不通过 → 确认幻觉，修正后标记可信区间
    │    验证       │
    └──────┬──────┘
           │ 通过
    ┌──────▼──────┐
    │  L3 领域专家  │ ← 不通过 → 需要更深入的专业判断
    │    判断       │
    └──────┬──────┘
           │ 通过
      ✔ 可信输出
```

### L1：内部一致性检查清单

- [ ] 回答内部有逻辑矛盾吗？（同一段内冲突的陈述）
- [ ] 推理链完整吗？有跳跃的步骤吗？
- [ ] AI 是否回答了不是我问的问题？
- [ ] AI 是否回避了问题的核心部分？
- [ ] 用反向 prompt 测试：请 AI 反驳它自己的回答

### L2：事实交叉验证清单

- [ ] 关键数字/日期能从独立来源确认吗？
- [ ] 引用的文献/研究真实存在吗？（直接搜索）
- [ ] 引用的政策、法规、标准是最新版本吗？
- [ ] 对于事实性问题，用不同的 prompt 问同一个 AI，结果一致吗？
- [ ] 用另一个 AI 模型交叉验证关键事实

### L3：领域专家判断清单

- [ ] 这个结论在你的专业经验中合理吗？
- [ ] AI 是否忽略了该领域的关键约束条件？
- [ ] AI 的假设在你的业务场景中成立吗？
- [ ] AI 没有提到的内容是否同样重要？（沉默的盲点）

## Prompt 工程作为批判性思维的外化

好的 prompt = 好的批判性思维。每次写 prompt 时，你实际上在进行：

| 批判性思维技能 | 对应的 Prompt 技术 | 示例 |
|---------------|-------------------|------|
| 明确问题边界 | 约束条件设定 | "只考虑 2024-2026 年的数据" |
| 识别假设 | 显式需求陈述 | "假设用户是初级开发者" |
| 要求证据 | 推理链要求 | "请分步推理，每步给出依据" |
| 考虑反方观点 | 对立视角 prompt | "请从反面论证这个方案" |
| 评估可信度 | 置信度标注 | "请标注每个结论的置信度，并说明原因" |
| 识别盲点 | 漏洞检查 prompt | "我的分析中可能忽略了哪些因素？" |

**策略：** 如果你发现自己不知道怎么写 prompt，说明你对问题的理解还不够清晰。先整理思路，再写 prompt——prompt 是你思维的输出，不是输入。

## 常见认知陷阱

### 自动化偏见（Automation Bias）

> 因为输出来自"AI"，所以倾向接受而不质疑。

**症状：** 直接复制 AI 输出到工作文档，不做验证。
**解药：** 强制自己每段至少做一次 L1 检查。

### 确认偏误（Confirmation Bias）

> AI 更倾向于强化你的已有观点，因为你的 prompt 已经暗示了立场。

**示例：**
- 你写的 prompt："分析为什么微服务比单体架构好" → AI 列举微服务优势
- AI 没有主动说"但微服务也有显著的运维成本"

**解药：** 写 prompt 时故意加入反方视角，或先不给立场让 AI 先分析利弊。

### 过度外推（Over-extrapolation）

> AI 说了一个对的事实 → 你相信它说的其他事实也对。

**问题：** AI 在某个领域表现好，不代表在所有领域都可靠。同一个回答中，事实部分可能是对的，推理部分可能是错的。

**解药：** 对每个输出做分维评估——事实、推理、假设、建议——不同维度可信度可能差异很大。
