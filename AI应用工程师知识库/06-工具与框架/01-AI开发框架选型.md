## 2. Python框架详解

### 2.1 LangChain

**定位：** 最通用的LLM应用开发框架

**核心模块：**
```
LangChain
├── langchain-core          # 核心抽象（消息、提示、输出解析）
├── langchain-community     # 社区集成（第三方工具）
├── langchain-openai        # OpenAI集成
├── langchain-anthropic     # Anthropic集成
├── langchain-huggingface   # HuggingFace集成
└── langchain-milvus        # 向量数据库集成
```

**适用场景：**
- 快速原型开发
- 标准RAG应用
- 简单Agent系统
- 多供应商切换

**代码示例：**
```python
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

# 基础链
model = ChatOpenAI(model="gpt-4o")
prompt = ChatPromptTemplate.from_template("翻译以下中文到英文: {text}")
parser = StrOutputParser()

chain = prompt | model | parser
result = chain.invoke({"text": "你好世界"})
```

**优缺点：**

| 优点 | 缺点 |
|------|------|
| 生态最丰富 | 版本更新快，API变动大 |
| 集成最多 | 抽象层较厚，调试困难 |
| 文档完善 | 性能一般 |
| 社区活跃 | 部分功能过度设计 |

**版本建议：** 使用 0.2.x 稳定版

### 2.2 LangGraph

**定位：** 复杂状态机与Agent编排

**核心概念：**
```
StateGraph
├── State: TypedDict定义状态
├── Node: 执行节点（函数）
├── Edge: 普通边
├── ConditionalEdge: 条件边
└── Memory: 持久化状态
```

**适用场景：**
- 多轮对话Agent
- 复杂工作流
- 需要状态持久化
- 人机协作

**代码示例：**
```python
from langgraph.graph import StateGraph, END
from typing import TypedDict, Annotated
import operator

class AgentState(TypedDict):
    messages: Annotated[list, operator.add]
    next_step: str

# 定义节点
def router(state):
    if "搜索" in state["messages"][-1]:
        return {"next_step": "search"}
    return {"next_step": "answer"}

def search(state):
    # 执行搜索
    return {"messages": [{"role": "tool", "content": "搜索结果"}]}

def answer(state):
    # 生成答案
    return {"messages": [{"role": "assistant", "content": "答案"}]}

# 构建图
graph = StateGraph(AgentState)
graph.add_node("router", router)
graph.add_node("search", search)
graph.add_node("answer", answer)

graph.set_entry_point("router")
graph.add_conditional_edges("router", lambda s: s["next_step"], {
    "search": "search",
    "answer": "answer"
})
graph.add_edge("search", "answer")
graph.add_edge("answer", END)

app = graph.compile()
```

**与LangChain关系：**
- LangGraph基于LangChain构建
- 可复用LangChain的组件（模型、提示、工具）
- 提供更强大的流程控制能力

### 2.3 LlamaIndex

**定位：** RAG-first的框架

**核心优势：**
- 开箱即用的RAG Pipeline
- 丰富的数据连接器
- 高级检索策略
- 与LangChain可互操作

**适用场景：**
- 知识库问答
- 文档检索
- 多数据源整合

**代码示例：**
```python
from llama_index.core import VectorStoreIndex, SimpleDirectoryReader
from llama_index.core.query_engine import RetrieverQueryEngine

# 加载文档
documents = SimpleDirectoryReader("./docs").load_data()

# 创建索引
index = VectorStoreIndex.from_documents(documents)

# 查询
query_engine = index.as_query_engine()
response = query_engine.query("什么是RAG？")
print(response)
```

**高级功能：**
```python
# 多路检索
from llama_index.core.retrievers import QueryFusionRetriever

retriever = QueryFusionRetriever(
    [vector_retriever, bm25_retriever],
    similarity_top_k=10,
    num_queries=4,
    mode="reciprocal_rerank"
)

# 子问题查询
from llama_index.core.query_engine import SubQuestionQueryEngine

query_engine = SubQuestionQueryEngine.from_defaults(
    query_engine_tools=tools
)
```

### 2.4 CrewAI

**定位：** 多Agent协作框架

**核心概念：**
```
Crew
├── Agent（角色定义）
├── Task（任务定义）
├── Process（执行流程）
└── Tools（工具集）
```

**适用场景：**
- 业务流程自动化
- 多角色协作任务
- 报告生成
- 研究分析

**代码示例：**
```python
from crewai import Agent, Task, Crew, Process

# 定义Agent
researcher = Agent(
    role="研究员",
    goal="搜集和分析信息",
    backstory="资深研究专家",
    tools=[search_tool],
    verbose=True
)

writer = Agent(
    role="写手",
    goal="撰写报告",
    backstory="专业写手",
    verbose=True
)

# 定义任务
research_task = Task(
    description="研究{topic}的最新趋势",
    agent=researcher,
    expected_output="研究报告"
)

write_task = Task(
    description="基于研究撰写文章",
    agent=writer,
    expected_output="完整文章"
)

# 组建团队
crew = Crew(
    agents=[researcher, writer],
    tasks=[research_task, write_task],
    process=Process.sequential
)

result = crew.kickoff(inputs={"topic": "AI架构"})
```

## 3. Java框架详解

### 3.1 Spring AI

**定位：** Spring生态的AI集成框架

**核心特性：**
- 与Spring Boot无缝集成
- 声明式AI服务
- 支持多种模型供应商
- 企业级特性（安全、监控）

**适用场景：**
- 企业级Java应用
- Spring Cloud微服务
- 需要与现有Spring系统集成

**代码示例：**
```java
@Service
public class ChatService {
    private final ChatClient chatClient;
    
    public ChatService(ChatClient.Builder builder) {
        this.chatClient = builder
            .defaultSystem("你是一个专业助手")
            .build();
    }
    
    public String chat(String message) {
        return chatClient.prompt()
            .user(message)
            .call()
            .content();
    }
    
    public Flux<String> chatStream(String message) {
        return chatClient.prompt()
            .user(message)
            .stream()
            .content();
    }
}
```

**RAG集成：**
```java
@Component
public class RAGService {
    @Autowired
    private VectorStore vectorStore;
    
    public String query(String question) {
        // 检索相关文档
        List<Document> documents = vectorStore.similaritySearch(
            SearchRequest.query(question).withTopK(5)
        );
        
        // 生成回答
        return chatClient.prompt()
            .system("基于以下上下文回答问题：" + documents)
            .user(question)
            .call()
            .content();
    }
}
```

**支持的模型：**
- OpenAI
- Azure OpenAI
- Ollama（本地模型）
- Anthropic
- Google Vertex AI
- Amazon Bedrock

### 3.2 LangChain4j

**定位：** Java版LangChain

**核心特性：**
- 声明式AI Service
- 丰富的集成
- 与Quarkus/Spring兼容

**代码示例：**
```java
// 定义AI服务接口
interface Assistant {
    @SystemMessage("你是一个专业助手")
    String chat(@UserMessage String message);
    
    @SystemMessage("提取实体")
    List<Entity> extract(@UserMessage String text);
}

// 使用
Assistant assistant = AiServices.create(Assistant.class, chatModel);
String answer = assistant.chat("你好");

// 带工具
Assistant assistant = AiServices.builder(Assistant.class)
    .chatLanguageModel(chatModel)
    .tools(new CalculatorTools())
    .build();
```

**与Spring AI对比：**

| 特性 | Spring AI | LangChain4j |
|------|-----------|-------------|
| Spring集成 | 原生 | 兼容 |
| 声明式 | 配置为主 | 注解为主 |
| 学习曲线 | 中等 | 平缓 |
| 生态 | Spring生态 | 独立生态 |
| 企业特性 | 强 | 中等 |

## 4. 框架选型建议

### 4.1 场景化选型

| 场景 | 推荐框架 | 理由 |
|------|----------|------|
| **快速原型** | LangChain | 生态丰富，快速上手 |
| **复杂Agent** | LangGraph | 状态机控制，流程清晰 |
| **知识库问答** | LlamaIndex | RAG-first，开箱即用 |
| **多Agent协作** | CrewAI | 角色定义清晰，流程化 |
| **企业Java应用** | Spring AI | Spring生态，企业级支持 |
| **Java微服务** | LangChain4j | 轻量，与框架无关 |

### 4.2 技术栈组合建议

**组合1：Python全栈**
```
LangChain/LangGraph + FastAPI + Milvus + React
```

**组合2：Java全栈**
```
Spring AI + Spring Boot + PostgreSQL/pgvector + Vue
```

**组合3：混合架构**
```
Python AI服务（LangChain）+ Java业务服务（Spring Boot）
通过gRPC/REST通信
```

## 6. 开发者Checklist

### 6.1 框架选择Checklist

- [ ] 明确技术栈（Python/Java）
- [ ] 评估项目复杂度
- [ ] 确定是否需要复杂Agent编排
- [ ] 评估RAG需求强度
- [ ] 考虑团队技术背景
- [ ] 评估企业级需求（监控、安全）
- [ ] 检查框架版本稳定性
- [ ] 评估社区活跃度

### 6.2 常见陷阱

**陷阱1：框架版本冲突**
- 问题：LangChain 0.1和0.2 API不兼容
- 解决：锁定版本，升级前充分测试

**陷阱2：过度抽象**
- 问题：框架封装太厚，难以调试
- 解决：了解底层API，必要时绕过框架

**陷阱3：忽视性能**
- 问题：框架 overhead 导致延迟增加
- 解决：性能测试，必要时优化或自研
